**QR Code & Barcode Scanner** (`qrcode-barcode-scanner`) decodes and
*grades* QR codes that break standard scanners: artistic and AI-generated
symbols with damaged finders, low module contrast, art texture over data,
logos over the center. It powers the [qrcode-ai.com](https://qrcode-ai.com)
verify flow. Five runtime entry points are published from one Rust core:
Rust, CLI, Node native, browser WASM and Python.

## What makes it different

1. **A deterministic multi-engine decode ladder** — rxing (ZXing lineage)
   + rqrr (quirc lineage) + curated preprocessing rungs. No RNG in the
   scanner: on a given platform, the same input, configuration and build
   give the same report — unbounded, or whenever the report says the
   budget cut nothing (`trace.budget_exhausted: false`). The one exception
   is rxing's PDF417 decoder, which breaks ties in randomized order.
2. **Score contract v5** — survival ramps across six stress axes with
   structural caps and the error-correction margin cap. The 0-100 value is
   a real *margin* measure, not "did it decode" — and a whole judgment or
   none: a budget never ships a partial score.
3. **Synthetic UEC** — the ISO 15415 Unused Error Correction margin from
   RS syndromes (exact corrected-error counts; ISO's misdecode reserve is
   not subtracted, so on version 1, v2-L and v3-L a block with errors reads
   above ISO's value). Its `low_correction_margin` hint signals distrust;
   it does not prove a miscorrection or detect every wrong decode.
4. **An ISO 15415-informed grade card** — Symbol Contrast, Modulation,
   Axial Nonuniformity, Fixed Pattern Damage, UEC; honest by construction
   (hardware-only parameters reported absent, never faked).
5. **An erasure-rescue stage** — when both engines give up, the scanner
   re-decodes the bitstream itself with errors-and-erasures Reed-Solomon.
   Measured: center-logo occlusion tolerance grows from 20% to **30%
   radius** (2.2× the area).
6. **Exact content** — for the QR family, `content.raw` is the payload's
   original bytes and its ECI and FNC1 declarations are read once; other
   symbologies carry their decoding engine's reading re-encoded (ISO/IEC
   8859-1 when every character fits, else UTF-8). `charset: "unknown"` is
   the only lossy reading. Detections are the distinct contents the scanner
   can tell apart, never keyed on text. A malformed stream is refused, and
   so is a QR Code content whose every measured correction went past the
   standard's misdecode reserve (an `rqrr` decode of a grid the scanner
   cannot error-correct counts as one, at any version). Reads the scanner
   cannot measure (Micro QR, rMQR, other QR Code reads no parse measured)
   are published as read, and a correction inside the reserve can still
   be wrong: when the score measures the stream, a block whose errors
   spent all its parity raises `low_correction_margin` — which no
   errors-only correction inside the reserve does on version 1, v2-L and
   v3-L.

And it reads **every mainstream symbology**, not just QR: Micro QR · rMQR
· Data Matrix · Aztec · PDF417 · MaxiCode · EAN-13/8 · UPC-A/E ·
Code 128/39/93 · Codabar · ITF · GS1 DataBar · Telepen — every detection
labeled with its `symbology`, retail 1D codes classified as GTINs with a
check-digit verdict, GS1-128 and GS1 DataMatrix recognized via their
FNC1 symbology identifiers.

Plus **GS1 awareness** (element strings + Digital Link with a per-criterion
`conformant` verdict — Sunrise 2027-ready) and machine-actionable
**hints** that close the *generate → scan → act → regenerate* loop.

## The surfaces

| Artifact | Registry | For |
|---|---|---|
| `qrcode-barcode-scanner` | crates.io | Rust apps, Nika vision |
| `qrcode-barcode-scanner-cli` (`qrscan`) | crates.io | scripts, CI gates |
| `@qrcode-ai-com/qrcode-barcode-scanner` | npm | Node servers (async, libuv pool) |
| `@qrcode-ai-com/qrcode-barcode-scanner-wasm` | npm | browsers (one portable WASM, no SIMD) |
| `qrcode-barcode-scanner` | PyPI | Python — abi3 wheels, declared CPython 3.8 → 3.14 compatibility |
| Kotlin/Android · Swift/iOS | built from source | native mobile (UniFFI) |
| Flutter package | pub.dev, not yet published | Flutter — typed `ScanReport` (flutter_rust_bridge) |

<Note>
The Rust core, CLI, Node native, browser WASM and Python packages are public in
**0.11.0**. The six native npm platform packages are automatic dependencies of
the Node parent. Mobile bindings, JSR, agent adapters and container images have
separate publication and qualification gates. Old package versions remain
available under their historical names; the
[migration guide](/guides/migrate-to-qrcode-barcode-scanner) maps each name.
</Note>

Every surface speaks the **same JSON report** — one contract, machine-validated
against the [normative spec](https://github.com/qrcode-ai-com/qrcode-barcode-scanner/tree/main/spec)
in CI.

## Measured accuracy

| Corpus | Result |
|---|---|
| zxing blackbox (179 images, ground truth) | **169/179** exact-text @ 0° — at or above ZXing's own 0° pass thresholds on every suite: above on four, equal on the two whose thresholds are every image |
| qrcode-ai.com production templates | **15/15** decoded (incl. the blob-pixel class) |
| Center-logo occlusion (v5-H) | engines die >20% radius · **rescue decodes through 30%** |
