Choose a scanner around the work your application needs to do: decode a QR image,
run a camera interface, read several barcode formats or inspect a QR design's
scanning margin. QR Code & Barcode Scanner combines local decoding with a
structured report and QR-specific diagnostics. Those are useful integration
features; they do not establish a higher detection rate or lower latency than
another library.

**Reviewed on 13 November 2026.** Our row describes the published **0.11.0**
contract. The alternatives are pinned source snapshots, linked below; their
branches can differ from registry releases. This is a documentation comparison.
No common-corpus performance comparison was run for this page, and none of the
alternatives was installed or device-qualified by this review. Engine **0.12
remains unreleased**.

## Match the interface to the job

These projects cover different layers. A camera integration and a decoder library
can be alternatives for an application without exposing the same API. Documented
formats below are examples rather than a count-based ranking.

| Project | Documented format scope | Interface described by its source | Project license |
| --- | --- | --- | --- |
| **QR Code & Barcode Scanner 0.11.0** | QR family, linear barcodes and other 2D formats, including Code 128 and Data Matrix | Rust core, `qrscan` CLI, native Node/Python and browser WASM; shared scan-report contract with content, measured occurrences and QR diagnostics. [Report][our-report] · [published artifacts][our-surfaces] | [AGPL-3.0-or-later or commercial terms][our-license] |
| **ZXing-C++** | Linear and matrix formats, including EAN/UPC, Code 128, Data Matrix and the QR family | C++ library with `ReadBarcodes`, format selection, language wrappers and WebAssembly. Its README also documents barcode writing. [Source][zxing] | [Apache-2.0][zxing-license] |
| **html5-qrcode** | QR and multiple barcode formats, including Code 128, EAN-13 and Data Matrix | Browser camera/file scanning, a ready-made `Html5QrcodeScanner` UI and a lower-level `Html5Qrcode` API. [Source][html5] | [Apache-2.0][html5-license] |
| **Nimiq qr-scanner** | QR codes | Browser camera and single-image API; native `BarcodeDetector` when available, with a worker-based fallback. [Source][nimiq] | [MIT][nimiq-license] |
| **jsQR** | QR codes | JavaScript/TypeScript function over RGBA pixels; decoded bytes/text and location information. The application supplies camera capture and frame extraction. [Source][jsqr] | [Apache-2.0][jsqr-license] |
| **quirc** | QR codes, including multiple codes in an image | C library over grayscale pixels, with separate identification and decode steps; camera and inspection programs supplied as examples. [Source][quirc] | [ISC][quirc-license] |

The license links identify each project's text at the reviewed revision, rather
than summarizing every dependency's terms. Our portable skill is licensed
separately from the decoding engine; see the [licensing guide][our-license].

## When our scanner fits

**You need decoded content and physical occurrences in one report.** The
[report contract][our-report] groups detections by content identity and retains
measured physical occurrences separately. An application can show two copies of
the same QR payload without inventing two decoded values. Geometry is evidence
from the scan; not every detection has a measured quadrilateral.

**You inspect QR designs as well as reading their values.** The
[score contract][our-score] defines stress axes, correction-margin diagnostics
and hints for generator or template feedback. Scoring is QR-specific: it is not
a barcode-wide quality grade, an ISO-certified verifier measurement or a
guarantee of readability on every camera. Images and capture conditions affect
the result.

**You distinguish an empty result from unfinished work.** The
[profile and budget contract][our-profiles] exposes `trace.budget_exhausted`.
An interrupted judgment has `score: null`; the `frame` profile also omits scoring
by design. A configured budget is checked at work boundaries, so it is not a
hard real-time upper bound on call duration.

**You share decoding behavior across a browser and a backend.** The
[artifact manifest][our-surfaces] records the Rust/CLI, Node, WASM and Python
release files. The browser package's [camera documentation][our-camera] is
separate from those native interfaces. The browser camera UI does not
become a native mobile UI by installing a binding. Core decoding runs locally;
application uploads, downloaded input and optional caller-supplied destination
transport have their own network behavior.

## When another interface may fit

For a C++ application, ZXing-C++ supplies a native multiformat API and documents
both reading and writing. For a browser page needing ready-made camera/file
controls, html5-qrcode documents that UI directly; its reviewed README also
announces maintenance mode. That dated notice helps maintenance planning; it
is not a finding about scanning accuracy. [ZXing-C++][zxing] ·
[html5-qrcode][html5]

For QR-focused browser interactions, Nimiq qr-scanner documents camera handling
and a native-detector/worker path. If your application already owns RGBA frames,
jsQR exposes a direct JavaScript function. For C integrations owning grayscale
frames, quirc documents a decoder API and multiple-code iteration. These are
interface choices, not measured speed recommendations.
[Nimiq qr-scanner][nimiq] · [jsQR][jsqr] · [quirc][quirc]

Our pipeline also uses existing decoder work: the
[0.11.0 architecture][our-architecture] identifies `rxing` from the ZXing lineage
and `rqrr` from the quirc lineage. The surrounding report, recovery and scoring
layers do not make those components independent new decoders. There is no claim
here that these diagnostics are exclusive to this project or absent from every
alternative.

## What a performance comparison still needs

Detection rate, wrong reads, latency, memory and download size are **not measured
across these projects here**. A project's own benchmark, a synthetic fixture or
results from another machine cannot establish a relative winner.

A repeatable comparison must retain exact release/artifact hashes and build
options; the same labeled corpus and truth provenance; hardware, OS and runtime;
preprocessing and image-loading boundaries; warmup and cold-start policy; profile,
timeout and concurrency; and raw per-image results. Report correct content,
wrong content and missed content separately. Measure physical-occurrence recall
separately from content recall. Publish timing distributions and input limits
rather than an unqualified average.

Our [benchmark harness](https://github.com/qrcode-ai-com/qrcode-barcode-scanner/blob/v0.11.0/bench/README.md)
documents runtime and corpus methodology. It is not a completed head-to-head
study of these projects. Measured results can be added once the candidates,
adapters, corpus and retained receipts meet the same protocol.
