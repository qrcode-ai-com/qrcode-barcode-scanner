This pattern comes from the qrcode-ai.com editor's integration
([PR #11](https://github.com/supernovae-studio/qrcode-ai_landing/pull/11)):
one native-resolution scan replaces a 3-level canvas filter loop, and the
quality meter maps from a real margin score. It is a reference, not a
description of the live site: what the site runs depends on the package
version it ships, and the `NOT_JUDGED` status needs reports that carry
`trace.budget_exhausted` (score contract 5 and later).

<Note>
The examples consume the published
`@qrcode-ai-com/qrcode-barcode-scanner-wasm@0.11.0` package. Install it with
`npm install --save-exact @qrcode-ai-com/qrcode-barcode-scanner-wasm@0.11.0`.
Use the same package name for imports and dependency pre-bundling exclusions.
The [migration guide](/guides/migrate-to-qrcode-barcode-scanner) documents the
separate historical package.
</Note>

## The verify handler

```ts
import { ScanStatus } from "@/types/scan";
import { loadScanner } from "@qrcode-ai-com/qrcode-barcode-scanner-wasm/auto";

const onVerify = async () => {
  const canvas = previewRef.value?.canvas;
  if (!canvas) return;

  // The loader checks WASM support in this execution realm. Handle
  // ScannerInitError separately from scan errors in the calling UI. Its failed
  // attempt stays cached; retry only after an explicit user action with a fresh
  // createScannerLoader(), rather than retrying every verify/render.
  const { scan_image } = await loadScanner();

  // NATIVE resolution — no resize prep: downscaling destroys the blob
  // structure the deep ladder is calibrated for; the scanner caps engine
  // input internally
  const blob = await new Promise<Blob | null>((r) => canvas.toBlob(r, "image/png"));
  if (!blob) return;
  const bytes = new Uint8Array(await blob.arrayBuffer());

  // FULL profile: the blob/dot template class (an editor OUTPUT) only
  // decodes in the deep stage — `fast` would read NO on valid output.
  // 1500 ms bounds the scan once the PNG is decoded and normalized, at
  // attempt granularity: the decode, the normalization and the work spec/02
  // § Budget semantics lets run past the deadline all block the UI thread too.
  const report = scan_image(bytes, "full", undefined, undefined, 1500);
  const saturation = report.trace.saturation;
  const incomplete = report.trace.budget_exhausted !== false ||
    (["reads", "detections", "occurrences"] as const).some(
      (flag) => saturation?.[flag] !== false,
    );

  if (!report.detections.length) {
    // An incomplete or older unknown-capacity report cannot establish absence.
    scanStatus.value = incomplete ? ScanStatus.NOT_JUDGED : ScanStatus.NO;
  } else if (report.score === null) {
    // decoded, not judged within the budget — never read null as 0
    scanStatus.value = ScanStatus.NOT_JUDGED;
  } else {
    const score = report.score.value; // a present score is always complete
    scanStatus.value =
      score >= 80 ? ScanStatus.HIGH : score >= 60 ? ScanStatus.MEDIUM : ScanStatus.LOW;
  }
};
```

`NOT_JUDGED` is a status of its own. An empty result is inconclusive when
the budget ran out, a capacity was reached, or capacity flags are absent.
A decoded primary QR without a score is also unmeasured. For an exhausted
budget, offer an explicit re-scan off the critical path with a larger budget
or `0` (unbounded). More time does not remove a capacity limit: inspect its
flags and narrow the selected input or handle the incomplete result.
A present score measures the primary QR; it does not prove that every code
in the image was found.

## The status mapping

| Meter | Condition | Meaning for the user |
|---|---|---|
| HIGH | score ≥ 80 | high measured margin for the primary QR; device compatibility remains unverified |
| MEDIUM | 60-79 | intermediate measured margin; verify the intended capture conditions |
| LOW | decoded, < 60 | low measured margin; review encoding, contrast and capture conditions |
| NO | no detection, budget not exhausted and all three saturation flags present and false | no code decoded by this completed search |
| NOT_JUDGED | decoded without a score, or no detection in an incomplete/unknown-capacity report | inconclusive; inspect limits and re-scan explicitly |

## Transparent designs — the placement flow

A transparent PNG has no one background: the verdict depends on where it
lands. The engine flattens transparent inputs before scanning (`auto`
default) and reports the placement story in `report.alpha` — wire it into
the editor:

1. **Ask where the code will live** (once, softly). Known background →
   pass it: `alpha_background: "#1a1a2e"` — the score becomes THE score on
   the user's real surface. Unknown → keep `auto` and render the
   **safety strip** from `alpha.envelope` ("works on light backgrounds ·
   safe luma 160-255") plus a placement carousel: composite the design
   over each probed background client-side (canvas fill + `drawImage` —
   the PNG's alpha composites naturally) with the probe's ✓/✕.
2. **Probe your theme palette in the same scan** —
   `alpha_palette: ["#f5f5f4", "#1c1917"]` returns per-color verdicts in
   `alpha.envelope.palette`, instead of one full scan per candidate
   (max 32 colors — the bindings reject more, loudly).
   Debounced verify-while-typing? Skip the sweep during typing
   (`score_skip_checks: ["alpha_envelope"]`) and run it on idle/export —
   the flatten and score are untouched either way.
3. **Map the two alpha hints**: `alpha_background_dependent` → "this
   design only survives {placement} backgrounds" ·
   `add_background_plate` → a one-click "add a {color} plate" action
   (rounded rectangle + quiet-zone margin behind the symbol — the
   canonical designer fix).

<Warning>
**The JPG trap.** JPEG has no alpha channel, and a `<canvas>` exported to
JPEG silently flattens transparency onto **black** — a dark-modules design
becomes an unscannable file. Never flatten silently at export: offer an
explicit background choice (then verify with that exact
`alpha_background`), or steer the user to PNG. And always score **the
exact bytes you ship**: re-scan the exported file, not the preview.
</Warning>

Don't forget the Vite exclude
(`optimizeDeps.exclude: ["@qrcode-ai-com/qrcode-barcode-scanner-wasm"]`), with
the name of the package you installed.
