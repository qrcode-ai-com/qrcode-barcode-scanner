One Rust core, five published runtime entry points and separate mobile bindings, the [same JSON report](/api/report). Pick by where
your code runs:

| Your context | Surface | Install |
|---|---|---|
| Rust app / service | [`qrcode-barcode-scanner`](/api/rust) | `cargo add qrcode-barcode-scanner@=0.11.0` |
| Shell scripts, CI gates | [CLI `qrscan`](/api/cli) | `cargo install qrcode-barcode-scanner-cli --version 0.11.0 --locked` |
| Node server (Nuxt/Next/worker) | [`@qrcode-ai-com/qrcode-barcode-scanner`](/api/node) | `npm install --save-exact @qrcode-ai-com/qrcode-barcode-scanner@0.11.0` |
| Browser | [`…-wasm`](/api/wasm) | `npm install --save-exact @qrcode-ai-com/qrcode-barcode-scanner-wasm@0.11.0` |
| Python | [`qrcode-barcode-scanner`](/api/python) | `python -m pip install qrcode-barcode-scanner==0.11.0` |
| Native Android / iOS | [Kotlin / Swift](/api/mobile) | from source |
| Cross-platform app | [Flutter](/api/flutter) | from source, not yet on pub.dev |

<Note>
The five runtime packages are public in 0.11.0 under these names. Node selects
one matching native platform dependency automatically; the browser package
contains one portable WASM plus its included camera and overlay modules.
The [migration guide](/guides/migrate-to-qrcode-barcode-scanner) keeps old
packages separate. Flutter, Kotlin and Swift retain their source-build and
qualification limits; a binding is not a mobile application.
</Note>

## What each surface needs to *install*

- **Rust / Cargo CLI** — a Rust toolchain. The release also provides prebuilt
  CLI archives, which need no Rust compiler at installation.
- **Node / WASM** — the published native dependency or portable `.wasm`.
  No Rust toolchain is needed to consume these packages.
- **Python** — a matching published `abi3` wheel needs no Rust toolchain;
  a source build does. See the [wheel platforms and tested interpreter](/api/python).
- **Kotlin/Android** — source build; no qualified JitPack release is claimed.
  Building needs Rust and the Android NDK.
- **Swift/iOS** — source build of the `.xcframework`; the package cannot be
  added by repository URL. Rust and the platform SDK are needed to build it.
- **Flutter** — unpublished on pub.dev. Its source binding compiles Rust at
  application build time through cargokit and needs the relevant platform toolchain.

Container and agent adapters reuse these runtimes but keep separate publication
and consumer evidence. The published MCP adapter, ClawHub skill and OpenClaw
bundle are documented in the [agent integration guide](/guides/agents), including
their installed-consumer scope. They use existing scanner runtimes and do not
add a sixth scanner SDK. Prepared integrations still require their own publication.

## Picking a profile

Every surface takes a `profile`: `full` (full ladder + scannability score — the
generator quality gate), `fast` (reduced, for upload tools), `frame` (per-frame
camera decode, no scoring). Default is `full` (`frame` for the `scanFrame` entry
points). Bound the worst case with a budget (see each surface's API page).

Whatever you pick, the result is the **same versioned [`ScanReport`](/api/report)** —
machine-validated against the [normative spec](https://github.com/qrcode-ai-com/qrcode-barcode-scanner/tree/main/spec)
in CI, so you can prototype on one surface and ship on another.
