## Invariants you can rely on

1. **Empty `detections` is success-with-nothing** — exit 1 on the CLI,
   resolved Promise elsewhere. Engine faults carry `QRS-\d{3}` codes;
   bindings and adapters also have input-validation errors of their own.
   An empty report is inconclusive if the budget flag is not explicitly
   `false` or any capacity flag is true or missing. Even a completed search
   establishes only that this build decoded no code from this input.
2. The JSON shape is identical on every surface and evolves additively —
   tolerate unknown fields/kinds/hints.
3. For the QR family, `content.raw` (base64) is the byte truth: the
   payload's original bytes. Other symbologies carry their decoding
   engine's reading re-encoded (ISO/IEC 8859-1 when every character fits,
   else UTF-8) and report no ECI. `text` is the one reading of `raw` and
   `charset` says how. `charset === "unknown"` is the ONLY lossy value,
   now and in every later version: then `text` is not a complete decoding
   — never act on it; use `raw` (with `content.eci`). Any other value,
   even one newer than your types, is a complete decoding the scanner
   checked byte for byte.
4. A content's identity is (`symbology`, `raw`, `fnc1`, compatible
   `eci`), never `text`. To check a QR-family symbol you generated,
   compare `raw` (and `eci`, `fnc1`) with what you encoded; for other
   symbologies compare `text`, or `raw` only when you encoded no ECI.
   `eci` is present only when an ECI was observed (`[]` when it could not
   be located); `fnc1` only for GS1 (`first`) or AIM-application
   (`second`) data. An absent key means none was observed, or the
   symbology does not report it — not that the symbol declares none.
5. **`trace.budget_exhausted` records a budget cut.** `false`:
   every planned unit ran, and the report equals the unbounded report for
   the same input, configuration and scanner build on the same platform
   (wall clock aside; PDF417 excepted — its decoder breaks ties in
   randomized order, spec/04 § Determinism). `true`: the wall-clock budget
   cut planned work. Then **re-scan unbounded first** (`--budget-ms 0`,
   `budgetMs: 0`, `budget_ms=0`); never regenerate, accept or reject on
   that report. Absent (older reports): unknown. The budget contract calls
   `false` final; it does not mean every symbol or copy was found.
   `trace.saturation.reads`, `.detections` and `.occurrences` record separate
   capacity limits. Any true or missing flag leaves search completeness
   unproven. Removing a time budget does not remove those capacities.
6. Cache only reports whose flag is `false`, keyed on the input + the WHOLE
   configuration (profile, budget, input limits, skipped axes and checks,
   alpha options) + `versions`, on the same build. Preserve saturation flags
   in the cached report; a cached limited or unknown-capacity result cannot
   establish absence.
7. **`score: null` is never `0`.** With detections it means the
   configuration computes no score (`frame`, every axis skipped), the
   budget interrupted the judgment (`trace.budget_exhausted: true` — not
   judged, re-scan), or a contained fault. A present score is always a
   complete judgment.
8. `meta`/`corners` are measured or `null` — never fabricated.
9. Some reads are refused rather than published: a malformed QR stream, a
   QR Code content whose every measured correction went past ISO/IEC
   18004's misdecode reserve (an `rqrr` decode of a grid the scanner
   cannot error-correct counts as one, at any version), and a UPC-E,
   DataBar or low-EC PDF417 read no independent read confirmed. This
   narrows wrong reads without ruling them out: reads with no measured
   margin (Micro QR, rMQR, other QR Code reads no parse measured) are
   published as read, and a correction inside the reserve can still be
   wrong — treat `low_correction_margin` as failure, and its absence as no
   proof: on version 1, v2-L and v3-L an errors-only correction at the
   reserve's limit reads a UEC margin above 0 and raises no hint (spec/04
   § Synthetic UEC).

## The regenerate loop

```text
generate(params) → scan(full) →
  ├─ budget flag true        → re-scan unbounded before judging
  ├─ budget flag missing     → inspect report version; result is inconclusive
  ├─ any saturation flag true or missing → inspect limits/version; narrow input if needed
  ├─ no detection            → adjust per trace (which stage died) + retry
  ├─ hints non-empty         → apply the mapped fixes:
  │    fix_finder_pattern{corner} → clear art at that corner
  │    restore_quiet_zone        → add border margin
  │    increase_contrast         → darken modules / lighten bg
  │    enlarge_modules           → shorter content or bigger render
  │    reduce_art_texture        → lower texture strength over data
  │    raise_error_correction    → bump EC level (l→m→q→h)
  │    low_correction_margin     → TREAT AS FAILURE (miscorrection risk)
  └─ primary QR score ≥ threshold & hints ∅ → evaluate the application's quality gate
```

The hints were designed to be actionable **without image analysis** — an
agent can drive generation parameters from the report alone.

## Example QR quality gates

These are application heuristics for a measured primary QR, not validated
device-compatibility, print-quality or retail certification thresholds. Check
the intended capture conditions and devices. A score does not prove that every
code was found; GS1 payload conformance checks syntax within the validator's
supported subset, not retail-system acceptance.

| Context | Gate |
|---|---|
| QR on a display | decoded + score ≥ 60 |
| printed QR proof | score ≥ 80 AND `score.uec.grade` ∈ `{a, b}` AND no hints |
| GS1 QR payload check | the above AND the selected detection's `payload.conformant === true` |
| ANY content you act on | reject if `low_correction_margin` present (its absence is no proof on v1, v2-L and v3-L — invariant 9) |

## CLI patterns for tool use

```bash
qrscan in.png --budget-ms 0 | jq '{text: .detections[0].content.text,
                                   charset: .detections[0].content.charset,
                                   kind: .detections[0].payload.kind,
                                   score: .score.value,
                                   budgetExhausted: .trace.budget_exhausted,
                                   capacityLimitedOrUnknown:
                                     ([.trace.saturation.reads,
                                       .trace.saturation.detections,
                                       .trace.saturation.occurrences] | any(. != false)),
                                   hints: [.hints[].hint]}'
```

Gate on `charset` before acting on `text`: `"unknown"` means the scanner
could not read every byte. `budgetExhausted` preserves `true`, `false` or
`null` for an absent flag. An empty detection list is inconclusive unless
`budgetExhausted` is `false` and `capacityLimitedOrUnknown` is `false`.
`--budget-ms 0` removes the time budget and enables reproducibility under the
same build/configuration contract (PDF417 excepted); it does not remove
capacity limits or certify complete detection.

Exit codes are the branch signal: `0` decoded · `1` nothing · `2` fault
(or, with `--score-only`, a configuration that computes no score) · `3`
(`--score-only` only) decoded, but not judged within the budget — re-scan
with `--budget-ms 0`.
