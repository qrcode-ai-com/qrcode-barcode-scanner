## Automatic initialization

```ts
import { loadScanner } from "@qrcode-ai-com/qrcode-barcode-scanner-wasm/auto";
const scanner = await loadScanner();
const report = scanner.scan_image(bytes, "full");
const loadedVariant = scanner.variant; // "portable"
```

Use this entry in both the module worker and any main-thread fallback. It
checks real WASM features in the calling realm before compiling the scanner,
then fetches the package's one module. Imports are safe during SSR;
initialization still belongs to client/worker execution. Repeated and
concurrent calls share one promise, including an initialization failure. An
explicit user retry can create one fresh `createScannerLoader()`; there is no
blind retry or automatic reload.

`ScannerInitError` preserves its native `cause`, stable `code`, selected
`variant` and optional HTTP `status`. Missing WASM, unsupported baseline features,
loader imports, asset network/HTTP/read failures, invalid headers, ambiguous
WASM validation, compilation and instantiation have separate codes. A
validation failure in an unknown asset can reflect malformed code or unexpected
features. Inspect the actual asset and native cause instead of attributing every
error to a feature, browser age or CPU. These JS-only diagnostics do not change
the Rust `QRS-xxx` catalog or any scan report fields.

The loader requires mutable globals, bulk memory, sign extension, nontrapping
conversions, multivalue and reference types, and the module uses no SIMD. That
baseline does not promise compatibility with every WASM-capable browser. The
package's `build-info.json` records the module's hash, the features its code
uses, the compiled inputs and the build recipe. `variant: "compatible"` selects
this same module. The 0.10 `compatible/` export paths were removed: import the
package root instead. `"simd"` is no longer a variant and rejects with
`invalid_options`. The package README documents the baseline probe, the build
and the factory options. Physical devices, real Safari and historical browser
floors need their own acceptance evidence.

## Direct API

```ts
import init, { capabilities, scan_image, scan_frame, version }
  from "@qrcode-ai-com/qrcode-barcode-scanner-wasm";

await init(); // once — fetches + instantiates the .wasm

// encoded bytes (PNG/JPEG/WebP/GIF)
// args: bytes, profile?, max_dimension?, max_pixels?, budget_ms?,
//       score_skip_axes?, score_skip_checks?, alpha_background?
//       (alpha_background: "auto" | "white" | "black" | "none" | "#rrggbb"
//        — the background under transparent pixels; result in report.alpha)
const report = scan_image(bytes, "full", undefined, undefined, 1500);

// raw RGBA frames (live camera) — defaults to the `frame` profile
// args: data, width, height, profile?, budget_ms?, then scan_image's other
//       options in its order: max_dimension?, max_pixels?, score_skip_axes?,
//       score_skip_checks?, alpha_background?, alpha_palette?, score_preset?
const ctx = canvas.getContext("2d")!;
const img = ctx.getImageData(0, 0, canvas.width, canvas.height);
const frame = scan_frame(new Uint8Array(img.data.buffer),
                         canvas.width, canvas.height);

// the readers compiled into the module (spec/01 § Capabilities)
const { engines, symbologies } = capabilities();
```

`capabilities()` (typed `Capabilities`) says which readers the module
includes — `engines` in order `rxing`, `rqrr`, `rescue`, and the
`symbologies` they can return — not that an image will decode.

<Warning>
The scan runs **synchronously on the calling thread**. In UI contexts
either pass `budget_ms` (the verify flow uses 1500 ms) or move the call
into a Web Worker. `budget_ms: 0` (or a negative, `NaN` or `Infinity`)
means unbounded (reproducible); unset keeps the profile default. A
fractional budget floors to whole milliseconds, so a value strictly between
0 and 1 cuts the scan before its first stage; above 4294967295 throws
`[QRS-006]`. `max_dimension` / `max_pixels` take a whole number from 1 (to
4294967295 / `Number.MAX_SAFE_INTEGER`); `0`, a negative, a fraction, `NaN`
or an infinity throws `[QRS-006]`, never a wrapped or disabled cap
(`spec/02-profiles.md` § Option domains). The budget clock
starts once the image is decoded and normalized, so decoding a large image
is bounded by `max_dimension` and `max_pixels`, not by `budget_ms`; the
budget then stops planned work at attempt granularity, and the bounded
work `spec/02-profiles.md` § Budget semantics lists may finish past it. A
report the budget cut says so (`trace.budget_exhausted === true`): a
`null` score beside a detection then means "not judged" — never read it
as 0.
</Warning>

## Camera capture and visual selection

From 0.11.0 the `/camera` and `/camera-overlay` entries add a camera capture
controller, a tracker of measured positions and a framework-free overlay with an
exact readout of the selected code. Importing either entry requests no camera,
touches no DOM and starts no timer, so both import safely during server
rendering. Decoding stays in your module worker: the controller hands it the RGBA
pixels of each frame and never creates a decoder of its own.

```ts
import { createCameraScanner, createDetectionTracker }
  from "@qrcode-ai-com/qrcode-barcode-scanner-wasm/camera";
import { createCameraOverlay }
  from "@qrcode-ai-com/qrcode-barcode-scanner-wasm/camera-overlay";

// The container holds the video and is positioned (position: relative, for example).
const overlay = createCameraOverlay({
  video,
  container,
  mount: { rail: railSlot, readout: readoutSlot }, // recommended: below the video
});
const tracker = createDetectionTracker({
  onChange: (snapshot) => overlay.update(snapshot), // every snapshot, in order
  onError: reportUiError,
});
let worker = await startWorker(); // loads /auto once; each request calls scan_frame
const camera = createCameraScanner({
  video,
  tracker, // updated before onResult, reset whenever a capture session ends
  scanFrame: (rgba, width, height, { signal, frame }) => {
    // Copy pixels only when a thumbnail is due, before the buffer is transferred.
    if (overlay.wantsFrameImage()) {
      overlay.setFrameImage(new ImageData(new Uint8ClampedArray(rgba), width, height), frame);
    }
    return worker.scan(rgba, width, height, { signal });
  },
  recover: async (_cause, { signal }) => {
    worker.terminate();
    worker = await startWorker({ signal });
  },
  onState: (change) => showCameraState(change),
  onError: (error) => showCameraError(error.code),
});

// From the camera button: the camera needs a secure context (HTTPS or localhost).
await camera.start();

// On unmount, in any order:
camera.stop();
tracker.destroy();
overlay.destroy();
```

`startWorker()` and `worker.scan()` are yours. The worker loads `/auto` once and
answers each request with `scan_frame(rgba, width, height)`, which uses the
`frame` profile; `worker.scan()` returns a promise of that `ScanReport`.
Transfer `rgba.buffer` to the worker rather than copying it. The package's
`examples/scanner.worker.js` is such a worker, and `examples/camera.js` wires
these parts in a page (see [Examples](#examples)).

**Aztec codes.** The engine reads an Aztec code only when the code lies over
the center of the image it scans, in every profile, so an Aztec code off to
one side of a camera frame goes unread: ask users to center it.

### Capture

`createCameraScanner(options)` opens the camera on `start()`. Its `state` is
`idle`, `starting`, `running`, `recovering`, `stopped` or `failed`, and `onState`
receives every transition with its `reason`, as well as every change of `muted`
or `stalled`.

- **Frames.** Capture follows `requestVideoFrameCallback` where the browser has
  it, and otherwise a timer that skips a capture whose sampled pixels have not
  changed; `frame.source` says which. The long edge of the scanned frame is
  capped at `maxDimension` (1280 by default): a smaller cap is faster but can
  lose narrow barcodes. The next frame is requested `intervalMs` (100) after each
  result, and one decode is in flight at a time, across stops and restarts.
- **Timeout and recovery.** A decode that takes longer than `decodeTimeoutMs`
  (5000) aborts `context.signal`, the only abort the controller makes. Your
  adapter must never settle while its decoder still works on the frame: on
  abort, terminate the worker, then reject. With `recover`, the state becomes
  `recovering` until your replacement decoder is ready, at most `maxRecoveries`
  (2) times per session, each within `recoverTimeoutMs` (20000). Without it, a
  timeout fails the session with `decode_timeout`.
- **Errors.** A failed session sends one `CameraScannerError` to `onError`, and a
  `start()` still pending rejects with that same error. Its `code` is listed
  below and its `cause` keeps the native error.
- **Stalls and mutes.** `stalled` turns true when no new frame arrives for
  `stallMs` (2000) while the camera runs unmuted, and a muted track pauses
  capture. Neither invents a frame: the tracker's deadlines remove the outlines
  while the decoded results stay.
- **Session ends.** `stop()`, a hidden page, `pagehide` and an ended track
  release the camera and end the session, and late permission answers and
  results are discarded. Call `start()` again once the page is visible.
- **Switching cameras.** `setConstraints(constraints)` ends the session,
  releases the current device, then opens the new constraints; before the first
  start it only stores them. The default is
  `{ facingMode: { ideal: "environment" } }`.
- **One decoder.** Load one scanner in one module worker and keep it for every
  frame and every image you scan: image scanning and the camera then share one
  WASM module and one initialization. The controller replaces that decoder
  only through `recover`.

| `code` | When |
| --- | --- |
| `unsupported` | no `navigator.mediaDevices.getUserMedia`, outside a secure context for example |
| `permission_denied` | `getUserMedia` rejected with `NotAllowedError` or `SecurityError` |
| `device_not_found` | `NotFoundError` |
| `device_busy` | `NotReadableError` or `AbortError` |
| `constraints_unsatisfied` | `OverconstrainedError`, or a `TypeError` from `getUserMedia` |
| `start_failed` | any other `getUserMedia` rejection |
| `play_failed` | `video.play()` rejected |
| `canvas_unavailable` | no 2D canvas context, or its pixels could not be read |
| `stream_ended` | the camera track ended |
| `decode_failed`, `decode_timeout`, `recover_failed` | `scanFrame` rejected or timed out, or `recover` failed |
| `callback_failed` | `onResult` or `tracker.update` threw (the session fails), or `onState` or the tracker's reset threw (reported only) |

### Tracking

`createDetectionTracker(options)` follows each measured copy of a code from
frame to frame. Passed to the controller as `tracker`, it receives every report
with the frame's `observedAt`, `epoch` and `sequence`, and a reset whenever a
capture session ends.

- **Identities.** A spatial track follows one measured copy, so two printed
  copies of one content are two tracks. A read without a measured position
  becomes a content track (`basis: "content"`), which claims no position. A
  track keeps its `id` and its display `slot` for life, and the decoded results
  (`snapshot.results`, one per content) are kept apart from the tracks.
- **Proof of absence.** A `ScanReport` proves a code gone only when its trace
  shows no budget cut and no read or detection saturation
  (`trace.budget_exhausted`, `trace.saturation.reads` and
  `trace.saturation.detections` all `false`). One copy of a code that is still
  read counts as gone only when `trace.saturation.occurrences` is `false` too. A
  bare array of detections proves nothing unless you pass `{ complete: true }`.
  To filter a report, pass `{ ...report, detections: kept }` and choose `kept`
  by content, never by position.
- **Time.** Outlines and identities expire by time, not by counting reports:
  with `onChange`, one timer wakes the tracker at its next deadline, so outlines
  leave when the evidence stops. `observedAt` is in milliseconds on the
  tracker's clock (`performance.now()` by default), as is a camera frame's
  `captureTime`; its `mediaTime` is in seconds on the media timeline.
  `geometry.age` and `snapshot.frameAge` give the display age.
- **Snapshots.** `update()`, `snapshot()`, `advance()`, `reset()` and
  `clear()` each return a new `TrackerSnapshot` object: tracks in slot order,
  results, the events of that call (`entered`, `held`, `lost`, `expired` and
  others), saturation flags and `nextDeadline`. Its `detection` fields are the
  engine's objects, by reference. `snapshot()` reads the state without
  changing it. `onChange` receives the snapshot of every `update()`, `reset()`
  and `clear()`, of an `advance()` or a timer wake that applied a transition,
  and of a successful `forget(id)`, which returns `true` (`false` for an
  unknown id). `destroy()` cancels the timer.

| Option | Default | Meaning |
| --- | --- | --- |
| `smoothing` | `0.35` | weight of each new measurement against the previous estimate; `{ kind: "none" }` turns smoothing off |
| `staleMs` | `1200` | geometry older than this is withheld, and tracked or held tracks become lost |
| `reacquireMs` | `2000` | how long an identity survives without new evidence; at least `staleMs` |
| `maxMisses` | `1` | consecutive complete misses shown as held before a track is lost |
| `retainMs` | `Infinity` | how long a result without a live track is kept; at least `reacquireMs` |
| `maxResults` | `32` | results kept; at least 16 |

`holdMs`, which earlier 0.11 development builds accepted, now throws a TypeError
that names `staleMs` and `reacquireMs`.

**Slow devices.** A frame keeps its geometry only when its result arrives less
than `staleMs` after the frame's `observedAt`. A later result still updates the
decoded results, and a content with no live track shows as a content track, but
it moves no outline: the spatial tracks of that code age, turn lost and lose
their outlines until faster frames return. If capture, transfer and decoding
can take that long where your page runs, raise `staleMs`, and `reacquireMs`
with it, since it must stay at least `staleMs`. The cost: when the evidence
stops (a stalled camera, a hung decoder, reports cut by their budget), an
outline stays at its last measured position for up to `staleMs`.

### Overlay

`createCameraOverlay({ video, container })` draws from tracker snapshots: one
rounded four-corner outline for each valid measured quad, a line for a scan
line and dots for partial points. It never invents a rectangle, and draws
nothing for a content track, a lost track or geometry the tracker withheld. Each
track keeps a number (`slot + 1`) and a color (`TRACK_COLORS[slot % 8]`) for
life, and a code measured entirely outside the visible area gets a numbered
badge at the edge of the view, with a chevron pointing toward the code
(`markers.edgeHints: false` removes it).

- **Updates.** Deliver every `onChange` snapshot, in order. A snapshot older
  than the last one applied is ignored and counted in `inspect().ignored`; an
  array or any other value throws a TypeError; after `destroy()`, an update
  does nothing.
- **Selection.** The scene, the rail and the readout share one selected code. It
  is chosen automatically until the user picks one, by a tap, the rail or a
  digit key, or until you call `select(id)`. `select(null)` returns to automatic
  choice, and `select()` returns `false` for an unknown id. `onSelect(track,
  result)` fires once the DOM is consistent, and `overlay.detection` is the
  readout's subject.
- **Effects.** Dimming and blur, and a color wash that is off by default
  (`effects`), leave sharp cutouts only around quads that were precise in two
  consecutive frames, and never dim or blur a marked code that the focus mode
  covers. They switch on after `dwellMs` (500) of continuous eligibility, and
  only once `cooldownMs` (1000, doubled under reduced motion) has passed since
  they last switched off; they switch off at once. `focus` is `"auto"` (every
  code until the user picks one, then the selected one), `"all"`, `"selected"`
  or `"off"`. Effects are presentation only: the overlay never writes to the
  video or to the capture canvas, so the decoder reads the same pixels.
- **Readout.** The exact symbology label (19 symbologies), its family, the
  payload kind and the complete decoded text, with invisible characters shown
  as named chips; the ECI, FNC1 and the exact bytes in Details; GS1 fields and
  issues verbatim; for an `http:` or `https:` URL, the encoded URL exactly as
  decoded with an Open button; and a destination slot for the URL of a `url`,
  `gs1_digital_link` or `me_card` payload.
- **Helpers.** `describeDetection`, `segmentText`, `symbologyFamily`,
  `parseObjectPosition`, `overlayMediaRect`, `projectOverlayPoint`,
  `projectOverlayGeometry`, `quadOutline` and `quadRegion` are pure functions,
  and `DEFAULT_LABELS`, `TRACK_COLORS` and `CAMERA_OVERLAY_CSS` are constants.
  `setOptions()` validates every setting before it applies any, `layout()`
  re-reads the video's layout, `inspect()` returns a frozen diagnostic,
  `clear()` empties the selection and the scene until the next update, and
  `destroy()` removes every node, listener, observer and timer.

### Layout

The overlay covers the video's content box inside `container`, which must
contain the video and be positioned. It reads the video's computed `object-fit`
(`contain`, `cover`, `fill`, `none` or `scale-down`) and `object-position`
(keywords, percentages, pixels, edge offsets such as `right 10px bottom 20px`,
and `calc()` of a percentage and pixels), and detects a horizontal mirror such
as `transform: scaleX(-1)`. The `fit`, `position` and `mirror` options override
what it reads.

- `overlay.alignment`, also `data-alignment` on the overlay root, is `aligned`
  or the first problem found, in this order: `no-frame`, `no-size`,
  `unsupported-transform`, `object-view-box`, `unsupported-fit`,
  `unsupported-position`, `no-media`, `frame-mismatch`. Anything but `aligned`
  hides the markers and effects rather than drawing them in the wrong place; the
  rail and the readout stay.
- The container and its ancestors may carry a positive uniform scale and a
  translation, nothing else. Between the container and the video, only a
  translation or a horizontal mirror is allowed. A rotation, a skew or any other
  flip gives `unsupported-transform`.
- Size changes, class and style changes on the video and the container, and a
  new capture session re-read the layout. After a stylesheet-only change
  elsewhere, call `layout()`.
- Keep `opacity`, `filter`, `mask`, `clip-path` and `mix-blend-mode` off the
  overlay root (`[data-qr-camera-overlay]`): each would cut the blur off from
  the video behind it.
- The rail and the readout render inside the video in a `regular`, `compact` or
  `minimal` arrangement chosen from its size, or wherever you `mount` them.
  Mounting both below the video keeps every code visible and tappable. `rail` is
  `"auto"` (shown for several codes, or when nothing is selected), `"multiple"`,
  `"always"` or `"never"`. With `rail: "never"` and `readout: false` the overlay
  renders no keyboard chooser: provide your own control that calls `select()`.

### Theming

The overlay reads these custom properties with fallbacks and never declares
them, so a value set on any ancestor applies.

| Property | Fallback | Use |
| --- | --- | --- |
| `--qr-scanner-color-0` to `--qr-scanner-color-7` | the matching `TRACK_COLORS` entry | the color of each track whose `slot % 8` is that index |
| `--qr-scanner-color-0-text` to `--qr-scanner-color-7-text` | `--qr-scanner-action-text` | the number drawn on that color; keep a contrast of at least 4.5:1 |
| `--qr-scanner-action-text` | `#000` | the default number color |
| `--qr-scanner-highlight` | `#F5F7FA` | the color of every track with `colors: "mono"` |
| `--qr-scanner-casing` | `rgb(0 0 0/55%)` | the casing under strokes, dots and badges |
| `--qr-scanner-surface`, `--qr-scanner-text` | `Canvas`, `CanvasText` | the rail and the readout; override both together |
| `--qr-scanner-focus` | `CanvasText` | the focus ring |

`scheme` (`"dark"` by default, `"light"` or `"inherit"`) sets the `color-scheme`
that `Canvas` and `CanvasText` follow on the overlay and its mounted parts. The
overlay injects one `<style>` element per document or shadow root it renders
into. Under a strict `style-src`, pass the policy's nonce as `styleNonce`, or
pass `styles: "none"` and serve `CAMERA_OVERLAY_CSS` in your own stylesheet;
per-element values go through the CSSOM, never a `style` attribute. The
overlay's selectors use `:where()`, so a consumer rule with a single class does
not override them: theme through the properties above, or use a more specific
selector.

### Accessibility

- The rail is a toolbar holding one radio group. Tab reaches it once; the arrow
  keys (mirrored in right-to-left text), Home and End move the focus; Enter or
  Space selects. Entries are named like `Code 1, QR Code`, and entries 1 to 9
  carry `aria-keyshortcuts`: a digit selects that code while the focus is in the
  rail or the readout. Screen readers in browse mode may take the digits, so the
  radios and the Previous and Next buttons remain the main path.
- Escape closes the full readout card. Otherwise it returns to automatic
  selection when the user had picked a code or passed one over, and in every
  other case it is left to the page, a host dialog for example. The overlay adds
  no document-level key listener.
- A visually hidden `role="status"` region announces the selection, the loss
  and return of the selected code, the number of codes and the outcome of each
  action. A held state is never announced. With `announceContent: "none"` (the
  default) no announcement contains decoded content; `"preview"` adds its first
  48 code points.
- `lang` (`"en"` by default) is set on the overlay and its parts; decoded
  content and URLs carry `lang=""`.
- Reduced motion (`prefers-reduced-motion`, or `motion: "reduce"`) removes the
  animations and doubles the effect cooldown. Where the browser reports
  `prefers-reduced-transparency`, blur and glow are off; where it does not,
  `effects: { blur: 0 }` is the reduced-effects setting. Forced colors remove
  the dimming, wash, blur and glow.
- Buttons and rail entries measure at least 44 by 44 CSS pixels, and the
  selected entry carries a border and a check mark: color is never the only
  cue.

### Destinations

The readout shows a destination slot for the URL of a `url`, `gs1_digital_link`
or `me_card` payload. Without `destinations` it reads "Destination not checked"
and offers no check. To let users check a destination, pass a verifier from
[`/destination`](#url-destination-checks):

```ts
import { createDestinationVerifier, createEndpointTransport }
  from "@qrcode-ai-com/qrcode-barcode-scanner-wasm/destination";

const verifier = createDestinationVerifier({
  transport: createEndpointTransport({ endpoint: "/api/destination", label: "App server" }),
});
const overlay = createCameraOverlay({ video, container, destinations: verifier });
```

- A check starts only when the user presses Check destination. The overlay then
  calls `resolve(candidate)` with no signal, since attempts are shared, and
  Cancel check calls `cancel(candidate)`. Nothing is checked on scan, and
  nothing is opened. A check is a real request through your transport, with
  whatever effect the destination attaches to it (see
  [URL destination checks](#url-destination-checks)).
- A resolved result reads "Destination observed" with the transport's label
  beside it, or "Example result (simulated)" with a Simulated badge for a
  prepared transport. Either is an observation of one request chain, never a
  safety verdict, and every URL in it renders as text.
- `destroy()` unsubscribes from the verifier but cancels no attempt, since
  other views may share it: cancel through the verifier, or destroy it.
- A verifier that throws, after `verifier.destroy()` for example, reaches
  `onError` once; the slot then reads "Destination checks unavailable" until
  `setOptions()` passes `destinations` again.
- To render your own destination row instead, pass `destinationSlot: false` and
  feed a `createDestinationSelection(verifier)` binder from the overlay: call
  `selection.select(overlay.detection)` in `onSelect`.

### Copy and Open

- Copy writes the exact decoded text with `navigator.clipboard.writeText()`. It
  is hidden when `actions.copy` is false or the Clipboard API is missing. Some
  platforms cut a text clipboard at U+0000 or rewrite line endings, so Details
  also offers Copy bytes, which copies the exact bytes as uppercase hexadecimal.
- Open appears only for an `http:` or `https:` URL, and a click calls
  `window.open(href, "_blank", "noopener,noreferrer")`; nothing opens by
  itself. `href` is the URL parser's serialization of the encoded URL, which
  the readout shows exactly as decoded.
- `onAction(action)` runs before every open, copy, check and cancel, and
  `action.preventDefault()` skips the overlay's own call, for a host that
  handles the action itself.

### Thumbnails

With `thumbnails: true`, or `{ size, refreshMs }`, rail entries show a crop of
each code from the frame the decoder read. The overlay never reads the video
for them: in `scanFrame`, before the buffer is transferred, ask
`overlay.wantsFrameImage()`, and only when it returns `true` pass a copy to
`overlay.setFrameImage(image, frame)`, as the wiring above does. Pass an
`ImageData` or `createImageBitmap(canvas)`, never a canvas, which could be
redrawn before its update. The overlay asks for at most one copy per
`refreshMs` (1000 by default) and only while a crop is due; it crops quads
only, never enlarges a crop, and closes every `ImageBitmap` it receives.

## URL destination checks

From 0.11.0, two optional JavaScript entries report where an encoded `http(s)`
URL leads. Decoding and the WASM module never use them. `/camera-overlay`
imports `destinationCandidate` to read eligibility and checks a destination
only through a verifier you pass it, from a user action.

| Entry | Runs in | Exports |
| --- | --- | --- |
| `/destination` | browsers, module workers, Node and SSR; no imports | `destinationCandidate`, `createDestinationVerifier`, `createDestinationSelection`, `resolveDestination`, `createFetchTransport`, `createEndpointTransport`, `createPreparedTransport`, `classifyAddress`, `classifyHost`, `DESTINATION_POLICY` |
| `/destination-node` | Node only (tested on 22 and 24) | `createNodeTransport`, `createDestinationEndpoint` |

This section describes browser behaviour from the web standards; no
Safari/WebKit or physical-device behaviour is claimed.

Importing an entry, creating a verifier and creating a transport send nothing
and start no timer. A request leaves only from `verifier.resolve()`,
`resolveDestination()` or a direct `transport.resolve()`, through the transport
the application passed in. A result describes one check: the requested URL,
the final URL and status observed, the redirect steps when the transport can
see them, the transport and its provenance. It never says whether a
destination is safe.

<Warning>
A check is a real `GET`, with whatever effect the destination attaches to it: a
counted visit, a used scan cap, a consumed one-time link. Start checks only
from an explicit user action. Render every URL of a result as text, never as a
link, a navigation target or an open action.
</Warning>

```ts
import {
  createDestinationSelection,
  createDestinationVerifier,
  createEndpointTransport,
} from "@qrcode-ai-com/qrcode-barcode-scanner-wasm/destination";

// Create once, in client code; creation has no side effects.
const verifier = createDestinationVerifier({
  transport: createEndpointTransport({ endpoint: "/api/destination", label: "App server" }),
});
const selection = createDestinationSelection(verifier, {
  onChange(view) { renderDestination(view); }, // { candidate, snapshot } or null
});

selection.select(detection); // whenever the displayed detection changes; null for none

// On the "Check destination" button:
const view = selection.view;
if (view?.candidate.eligible && verifier.canResolve) {
  await verifier.resolve(view.candidate);
}

// On teardown:
selection.destroy();
verifier.destroy();
```

`renderDestination` shows `view.candidate.encodedUrl`, the `requestUrl` when it
differs, and the snapshot's `state`. Treat a destination as observed only when
`snapshot.state === "resolved" && snapshot.provenance !== "simulated"`, and
show `snapshot.transport.label` beside it. Create the endpoint transport in
client code: a `/path` endpoint resolves against `globalThis.location`, so
creating it on a server, during server rendering included, throws a TypeError.

### Eligibility

`destinationCandidate(input)` takes a `Detection`, a `Payload` or a string and
returns a frozen candidate. It reads `payload.url` of the `url`,
`gs1_digital_link` (whatever its `conformant` flag says) and `me_card` kinds,
and tests a string as it is, with `source: null`.

| `reason` | When |
| --- | --- |
| `no_url` | another payload kind (`text` included), an empty URL field or an empty string |
| `lossy_text` | the detection's `content.charset` is `unknown` |
| `not_http` | the value does not start with `http://` or `https://` at its first character, ASCII case ignored: a leading space, `www.example.com` or a string of plain text |
| `control_or_space` | a control character, a space or other separator, a format character, a default-ignorable code point (a variation selector after an emoji included) or a lone surrogate, anywhere in the value |
| `invalid_url` | the WHATWG URL parser refuses the value |
| `credentials` | the value carries a user name or password |
| `too_long` | the value or its `requestUrl` exceeds 16384 UTF-16 code units |

Nothing is trimmed, joined or completed: the URL parser would delete tabs and
line breaks, and IDNA would delete invisible characters inside a host, so
checking the parsed form would request a URL the code does not contain. An
eligible candidate keeps `encodedUrl`, the exact string and the verifier's
key, apart from `requestUrl`, its WHATWG serialization without the fragment
(scheme and host lowercased, IDNA applied, default port removed, dot segments
resolved, percent-encoding added). Show `requestUrl` whenever it differs.
Eligibility is stricter than opening a link: a code with a space or an
invisible character is still displayed, but never checked.

### Transports

| Factory | `kind` | Provenance ceiling | Default `label` | Runs in |
| --- | --- | --- | --- | --- |
| `createFetchTransport({ scope: "network" })` | `fetch` | `network` | This browser | browsers, module workers |
| `createFetchTransport({ scope: "fixture", fixtureOrigin })` | `fetch` | `fixture` | Local fixture (this browser) | browsers, module workers |
| `createEndpointTransport({ endpoint, label })` | `endpoint` | `network`, or the `provenance` option | none: `label` is required | browsers, module workers |
| `createPreparedTransport(entries, options)` | `prepared` | `simulated` | Prepared example | any runtime |
| `createNodeTransport(options)` | `node` | `network`, or `fixture` in fixture mode | Server resolver (Node) | Node |

The label is shown with every result; UIs must not infer trust from `kind`.
Each built-in transport throws a TypeError or RangeError synchronously for an
invalid request, and every observation passes the same validation before it
is stored.

- **Fetch.** `scope` is required: without `"network"` or `"fixture"`, creation
  throws a TypeError, so a forgotten option never sends a real request. The
  request is a `GET` with `mode: "cors"`, `credentials: "omit"`,
  `cache: "no-store"`, `redirect: "follow"`, an empty `referrer` and
  `referrerPolicy: "no-referrer"`; the body is canceled unread. Before sending,
  in order: a server runtime (Node, Bun, Deno, no `location`) gives
  `transport_unsupported`, whatever `fetch` is injected; in fixture scope,
  another origin gives `out_of_scope`; a WHATWG Fetch bad port gives
  `blocked_port`; in network scope, an address literal that is not public or a
  special-use or malformed name gives `blocked_address`, and an `http:` target
  from an HTTPS page gives `mixed_content`. A rejected fetch gives
  `opaque_network_error` with `requestSent: null`, because the request may
  still have arrived; an opaque response gives `opaque_response`. The response
  is readable only when the destination allows CORS, which most sites do not.
  After a redirect, `redirects` and `hopCount` are `null` and the browser
  applies its own limit of 20 redirects. In fixture scope, a final URL outside
  `fixtureOrigin` gives `left_fixture` after the browser may already have
  contacted it; a fixture confines chains only when it grants CORS to explicit
  page origins, never `*` or `null`.
- **Endpoint.** `endpoint` is a `/path` on the page origin or an absolute
  http(s) URL on that origin. Another origin needs `crossOrigin: true`, meant
  only for third-party implementations of the wire that grant the CORS
  preflight. The transport sends one `POST` with `credentials: "same-origin"`
  by default (to the endpoint only, never to the destination),
  `redirect: "error"` and a `DestinationWireRequest` body whose `timeoutMs`
  leaves the client time to receive the server's timeout answer (9000 ms of
  10000). The answer is untrusted: a rejection gives `endpoint_unreachable`, a
  status other than 200 `endpoint_http_error`, no answer within the budget
  `endpoint_timeout`, and a body that fails validation (media type, 2 MiB cap,
  UTF-8, exact keys, chain rules, a provenance above the ceiling)
  `endpoint_invalid_response`.
- **Prepared.** Entries map a canonical `requestUrl` to a result, or to
  `"pending"`, which never settles by itself, for showing the resolving,
  canceled and timeout states. `delayMs` simulates latency. Every result has
  `requestSent: false`, and any other URL gives `out_of_scope`.
- **Custom.** Implement `DestinationTransport`: `kind: "custom"`, a `label` of
  1 to 80 code points, a provenance ceiling and a `resolve(request)` method
  that settles within `request.timeoutMs` and honours `request.signal`. An
  invalid observation gives `invalid_observation`, a throw or rejection
  `transport_error`, and a transport still pending 1000 ms after its budget
  `transport_unresponsive`.

### Verifier and results

`createDestinationVerifier(options)` returns a store with one entry per exact
`encodedUrl`.

| Option | Default | Range or meaning |
| --- | --- | --- |
| `transport` | required key | a transport, or `null`: every `resolve()` then settles `unavailable` with `no_transport` |
| `timeoutMs` | 10000 | 1 to 60000 ms per attempt; a transport still pending 1000 ms later is cut off |
| `maxHops` | 10 | 0 to 20 redirects |
| `maxConcurrent` | 2 | 1 to 8 attempts running |
| `maxQueued` | 16 | 0 to 256 attempts waiting, oldest first; beyond that, `queue_full` |
| `maxEntries` | 64 | more than `maxConcurrent + maxQueued`, at most 1024; beyond it, the least recently used settled entry returns to `unverified` |
| `timers` | platform clocks | `now`, `monotonic`, `setTimeout` and `clearTimeout`, called unbound |
| `reportError` | `globalThis.reportError`, else `console.error` | receives listener, transport and timer errors; never rethrows |

- `get(target)` returns the current snapshot, the same object until the entry
  changes, or `null` for an ineligible target. A target is a candidate or a
  string.
- `resolve(target, { signal })` starts an attempt, or joins the one in flight
  for the same `encodedUrl`; its promise never rejects. It throws a TypeError
  for an ineligible target, once `destroy()` has started, and for a signal that
  is not an `AbortSignal`. A settled entry keeps its result until the next
  `resolve()`, `forget()`, `clear()` or eviction; there is no expiry.
- `cancel(target)` cancels a queued or running attempt (`canceled`), and an
  aborted caller signal gives `aborted`. `forget(target)` and `clear()` return
  entries to `unverified`; an attempt in flight then resolves its promise
  `canceled` with `cleared`. `destroy()` clears the store and drops the
  listeners, and every later call except `destroy()` throws.
- `subscribe(listener)` delivers each stored change (`encodedUrl`, `snapshot`,
  `previous`, `cause`) synchronously and in order, and returns an idempotent
  unsubscribe function. `canResolve` and `transport` describe the
  configuration without exposing the transport object.

The methods are closures, so React can read the store directly:

```tsx
const snapshot = useSyncExternalStore(
  verifier.subscribe,
  () => (candidate?.eligible ? verifier.get(candidate) : null),
);
```

Every snapshot is frozen and has the same 18 keys: `encodedUrl`, `requestUrl`,
`state`, `reason`, `attemptId`, `transport`, `provenance`, `requestSent`,
`finalUrl`, `status`, `redirected`, `changed`, `redirects`, `hopCount`,
`startedAt`, `settledAt`, `durationMs` and `detail`.

| `state` | `reason` |
| --- | --- |
| `unverified`, `resolving` (`startedAt: null` while queued), `resolved` | `null` |
| `failed` | `timeout`, `too_many_redirects`, `redirect_loop`, `invalid_location`, `blocked_scheme`, `blocked_credentials`, `blocked_address`, `blocked_port`, `left_fixture`, `name_unusable`, `dns_error`, `connection_error`, `tls_error`, `invalid_response` |
| `unavailable` | from a transport: `transport_unsupported`, `out_of_scope`, `opaque_network_error`, `opaque_response`, `mixed_content`, `endpoint_unreachable`, `endpoint_http_error`, `endpoint_invalid_response`, `endpoint_timeout`, `resolver_busy`; from validation: `transport_error`, `invalid_observation`, `transport_unresponsive`; from the store: `no_transport`, `queue_full` |
| `canceled` | `canceled`, `aborted`; `cleared` appears only in the promise of a removed attempt |

- `provenance` is `network` (a real request to whatever the URL names),
  `fixture` (a real request to a local fixture) or `simulated` (prepared data,
  always with `requestSent: false`). An observation that claims more than its
  transport's ceiling is refused as `invalid_observation`, never upgraded.
- `requestSent` is `true` once a request left (for the fetch transport: the
  browser returned a response, which a service worker or its cache can also
  produce), `false` when provably none did, and `null` when unknown.
- `redirects` lists the redirect responses observed, each with `url`,
  `status`, `location` (`null` when invalid, credentialed or not http(s)) and
  `refusedScheme`. `hopCount` counts the redirects followed: a refused last
  step is observed but not followed. Both are `null` when the chain is unknown.
- `changed` says whether `finalUrl` differs from `requestUrl`.
- `startedAt` and `settledAt` come from the verifier's wall clock and
  `durationMs` from its monotonic clock. Time spent queued is excluded, and
  transports supply no times. Order attempts by `attemptId`.
- `detail` is English text of at most 300 code points. The built-in
  transports and the verifier write fixed sentences, some completed by an
  error code, a rule name or an HTTP status. A custom transport's or a
  prepared entry's `detail` is its own text, with control and invisible
  formatting characters replaced by U+FFFD. Only
  `DESTINATION_POLICY.detailSentences` cross the endpoint wire. Translate the
  `reason` codes for users.

`createDestinationSelection(verifier, { onChange, cancelOnDeselect })` binds
one verifier for its whole life. `select(input)` takes a detection, a payload,
a string or `null`. Its `view` is `{ candidate, snapshot }`, with `snapshot`
`null` exactly when the candidate is ineligible, and it always reads the
selected code's own entry, so a late result for another code never appears
under it. With `cancelOnDeselect: true` (default `false`), moving the
selection cancels the previous entry's attempt.

`resolveDestination(transport, { url, maxHops, timeoutMs, signal }, { timers })`
runs one validated call without a store and never rejects; its `outcome` is
`resolved`, `failed`, `unavailable` or `canceled`. `classifyAddress()` and
`classifyHost()` expose the address and name tables without any lookup, and
`DESTINATION_POLICY` holds the limits, the WHATWG Fetch bad ports, the fixed
detail sentences and the tables' `snapshot` date.

### Node resolver and endpoint

`/destination-node` imports `node:http`, `node:https` and `node:dns`; importing
it creates no socket, lookup, resolver, agent, server or timer.
`createNodeTransport()` checks at every call that it runs on Node and answers
`transport_unsupported` under Bun or Deno. On Node 22, importing `node:http`
from an ES module compiles a WebAssembly HTTP parser, so this entry needs
WebAssembly there and does not run under `--jitless`.

```ts
import { createDestinationEndpoint, createNodeTransport }
  from "@qrcode-ai-com/qrcode-barcode-scanner-wasm/destination-node";

const handler = createDestinationEndpoint({
  transport: createNodeTransport(), // one per process
  allowedHosts: ["app.example.com"],
});
// Before any body parser, on the page's own origin, behind your session check:
// app.post("/api/destination", requireSession, rateLimit, handler);
```

The resolver follows redirects itself and applies its policy on every hop:
http(s) only, bad ports refused and only `allowedPorts` reachable, special-use
names refused, every DNS answer vetted, public addresses only, a post-connect
address check, proxy settings ignored, certificate checks always on, bodies
never read. The handler accepts only same-origin JSON `POST` requests for an
allowed `Host`, and merges name failures into `name_unusable` by default. The
[security model](/concepts/security#destination-layer-optional-js-module)
details the policy and what the operator must still configure:
authentication, rate limits, NAT64 prefixes and denied ranges.

| --- | --- |
| `examples/headless.html`, `examples/headless.js` | Scans an image you choose or drop, in a module worker on your device: the image is never uploaded and decoded links stay text. The page names the package version, the SHA-256 of its WASM module and the version the loaded module reports. |
| `examples/camera.html`, `examples/camera.js` | Wires `createCameraScanner`, `createDetectionTracker` and `createCameraOverlay` as an application would: the camera opens only when you press its button, every tracker snapshot reaches `overlay.update(snapshot)`, a frame is copied only when `overlay.wantsFrameImage()` asks, and a hung frame replaces the worker through `recover`. Open is turned off, and destination checks stay off until you turn them on. |
| `examples/scanner.worker.js` | The module worker both pages use: it owns one scanner and answers `load`, `scan_image` and `scan_frame` requests by `id`. |
| `examples/ssr.mjs` | Imports `/camera`, `/camera-overlay` and `/destination` in Node, with each DOM, camera and network global it lists replaced by a trap, and prints what a server can compute with them. |

Module scripts and module workers do not run from a `file://` page. Serve the
package folder, the one that holds `package.json`, with a static server on
localhost that sends `.js` files with a JavaScript type, for example from a
project that installed the package:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory node_modules/@qrcode-ai-com/qrcode-barcode-scanner-wasm
```

Then open `http://127.0.0.1:8000/examples/headless.html` or
`http://127.0.0.1:8000/examples/camera.html`. The camera page needs a secure
context: `localhost` and `127.0.0.1` count as one on the machine that runs the
browser; from another device, such as a phone, serve the folder over `https`.
Run the server-rendering example with Node:

```bash
node node_modules/@qrcode-ai-com/qrcode-barcode-scanner-wasm/examples/ssr.mjs
```

[`examples/README.md`](https://github.com/qrcode-ai-com/qrcode-barcode-scanner/blob/main/crates/qrcode-ai-scanner-wasm/examples/README.md),
also in the installed package, describes each example and the worker's
messages.

### Content Security Policy

Both example pages scan with no violation reported when a server sends
`default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; img-src blob: data:`,
plus a `style-src` hash of the image page's one inline `<style>` element, as a
`Content-Security-Policy` header with every file of the package folder.
[`examples/README.md`](https://github.com/qrcode-ai-com/qrcode-barcode-scanner/blob/main/crates/qrcode-ai-scanner-wasm/examples/README.md#content-security-policy)
gives that exact policy, why each source is needed, and how the package's
browser job found it in Playwright's Chromium and Firefox. For a policy of your
own:

- **WebAssembly.** Compiling the module needs `'wasm-unsafe-eval'` in
  `script-src` in the policy of the context that compiles it; otherwise the
  browser refuses to compile it. A module worker loaded from its own URL takes
  its policy from the headers of that script's response: a page's `meta`
  policy, such as the one each example page carries, does not reach it.
- **Loader.** `/auto` imports the package's own module and fetches only its
  `.wasm` file, next to it unless you pass `wasmUrl`, so `connect-src`, or
  `default-src` when `connect-src` is absent, must allow that origin.
- **Overlay.** The overlay injects one `<style>` element, which needs
  `styleNonce` or `styles: "none"` with `CAMERA_OVERLAY_CSS` in your own
  stylesheet (see [Theming](#theming)), and sets every other value through the
  CSSOM.
- **Destinations.** A destination check requests only what its transport
  targets. Through `createFetchTransport()`, the page's `connect-src` must
  allow the link's origin, for example `connect-src 'self' https:`; otherwise
  the browser blocks the check before sending it, and the readout shows it as
  unavailable.

### SIMD, bundlers and server rendering

- **SIMD.** The package ships one module, which uses no SIMD, so a browser with
  WebAssembly SIMD disabled loads the same bytes; `scannerCapabilities().simd`
  is a diagnostic only. The package's browser job runs both example pages from
  the installed package in Playwright's Chromium and Firefox, and in CI also
  in a Chromium started with WebAssembly SIMD disabled. Those runs say nothing
  about Safari, iOS or Android.
- **Bundlers.** The examples need no bundler. In a bundled application, import
  the entries by name (`/auto`, `/camera`, `/camera-overlay`, `/destination`):
  the loader finds its `.wasm` through `import.meta.url`, and the package's CI
  builds a fresh Vite application with a module worker from the installed
  package. The settings each bundler needs are below, and
  [Use a bundler](https://github.com/qrcode-ai-com/qrcode-barcode-scanner/blob/main/crates/qrcode-ai-scanner-wasm/examples/README.md#use-a-bundler)
  shows the example pages' imports by package name.
- **Server rendering.** Importing `/auto`, `/camera`, `/camera-overlay` and
  `/destination` during server rendering compiles no WebAssembly, fetches
  nothing and touches no DOM; the package's CI imports them in Node with
  `WebAssembly` undefined and checks that `fetch` is never called, and
  `examples/ssr.mjs` shows the camera, overlay and destination helpers a server
  can call. Load the scanner in the browser or a worker, and start the camera
  in the browser: where WebAssembly is missing, `loadScanner()` rejects with
  `wasm_unavailable`.

## Bundler configuration

`/destination-node` has only a `node` export condition (no `import`, `default`
or `browser`), so a browser build fails to resolve it before bundling any
`node:` module, and because Bun also matches `node`, its transport checks the
runtime at every call.

<AccordionGroup>
  <Accordion title="Vite / Nuxt">
    Exclude from dependency pre-bundling — esbuild breaks the
    `import.meta.url` wasm resolution. Name the package you installed
    (`@supernovae-st/qrcode-ai-scanner-wasm` for 0.10.1):

    ```ts
    vite: { optimizeDeps: { exclude: ["@qrcode-ai-com/qrcode-barcode-scanner-wasm"] } }
    ```
  </Accordion>
  <Accordion title="Lazy loading">
    The release build reports the actual raw and gzip sizes; use the size
    of the version you install when setting a page-weight budget.
    Load it with the feature that needs it
    (dynamic `import()` in an async chunk) and memoize `init()` —
    **reset the memo if init rejects**, or one network error bricks the
    feature until reload:

    ```ts
    let ready: Promise<unknown> | null = null;
    ready ??= init().catch(err => { ready = null; throw err; });
    await ready;
    ```
  </Accordion>
  <Accordion title="Camera loop">
    Use `createCameraScanner` rather than a loop of your own: it requests the
    next frame `intervalMs` (100 ms by default) after each result and keeps one
    decode in flight, so a slow decode lowers the frame rate instead of queueing
    frames. Decode with `scan_frame` (no PNG roundtrip) and the `frame` profile.
  </Accordion>
</AccordionGroup>

Failures throw `JsError` with `[QRS-xxx]`-tagged messages
([catalog](/api/errors)).
