```bash
npm install --save-exact @qrcode-ai-com/qrcode-barcode-scanner@0.11.0
```

Prebuilt for macOS (arm64/x64), Linux (gnu+musl, arm64/x64), Windows
(x64). Full TypeScript types included.

The package reads encoded images (PNG/JPEG/WebP/GIF) through `scan` and
`scanSync`. It has no raw-frame entry and no camera or overlay interface:
those are the [browser package](/api/wasm)'s `scan_frame`, `/camera` and
`/camera-overlay`.

Each platform's addon is an optional dependency of the main package. When
the host's addon is absent (an install with `--omit=optional`, or a
platform without a prebuilt addon), `require` or `import` throws `Cannot
find native binding`; its `cause` chain names the platform package it
looked for, or the unsupported platform. That is a load failure, before
any scan, with no WASI fallback; scan rejections carry `[QRS-xxx]` codes
instead.

## API

```ts
import { capabilities, scan, scanSync, version } from "@qrcode-ai-com/qrcode-barcode-scanner";
import type { ScanReport, ScanOptions } from "@qrcode-ai-com/qrcode-barcode-scanner";

// async on the libuv pool — NEVER blocks the event loop
const report: ScanReport = await scan(imageBuffer, {
  profile: "full",        // "full" | "fast" | "frame"   (default full)
  budgetMs: 1500,         // wall-clock bound; 0 = unbounded
  maxDimension: 4096,     // anti-DoS — LOWER THESE for untrusted uploads
  maxPixels: 16_000_000,
  alphaBackground: "auto", // background under transparent pixels:
                          // "auto" | "white" | "black" | "none" | "#rrggbb"
                          // (opaque inputs untouched; result in report.alpha)
  signal: controller.signal, // cancels QUEUED tasks (see note)
} satisfies ScanOptions);

const sync = scanSync(buffer, { profile: "fast" }); // scripts only

// the readers compiled into the loaded addon (spec/01 § Capabilities)
const { versions, engines, symbologies } = capabilities();
```

`capabilities()` (typed `Capabilities`) says which readers are included —
`engines` in order `rxing`, `rqrr`, `rescue`, and the `symbologies` they
can return — not that an image will decode.

<Warning>
`signal` rejects a scan with an `AbortError` DOMException when it is
already aborted at the call or aborts while the task is still QUEUED on
the pool. A RUNNING scan is not interrupted: it settles as if not aborted,
with its report or its own `[QRS-xxx]` fault. Once its image is decoded,
its `profile`/`budgetMs` budget stops planned work at attempt granularity,
and the bounded work `spec/02-profiles.md` § Budget semantics lists may
finish past it. One signal may be shared by several scans: aborting it
rejects each of them still queued. Budget is the real
latency control — and a report it cut says so: `trace.budget_exhausted`
is `true`, empty detections are then not final, and a `null` score beside
a detection means "not judged", never 0. `budgetMs: 0` is unbounded and
reproducible; unset keeps the profile default (full 4000 · fast 800 ·
frame 80 ms). The budget clock starts once the image is decoded and
normalized: `maxDimension` and `maxPixels`, not `budgetMs`, bound the
decode itself.
</Warning>

The options are read as JavaScript numbers, the same way as the WASM
package (`spec/02-profiles.md` § Option domains). `budgetMs`: `0`, a
negative, `NaN` or `Infinity` is unbounded; a fraction floors to whole
milliseconds (`0.5` is a zero-millisecond budget, cut before the first
stage); above 4294967295 rejects. `maxDimension` / `maxPixels`: a whole
number from 1 (to 4294967295 / `Number.MAX_SAFE_INTEGER`); `0`, a negative,
a fraction, `NaN` or an infinity rejects — never a wrapped or disabled cap.
A refused option rejects with `[QRS-006]` before the image is read.

## Server recipe (Nitro/Express upload endpoint)

```ts
export default defineEventHandler(async (event) => {
  const body = await readRawBody(event, false);
  try {
    const report = await scan(body, {
      profile: "full", budgetMs: 2000,
      maxDimension: 4096, maxPixels: 16_000_000,
    });
    if (!report.detections.length) return { ok: false, reason: "no_qr" };
    const d = report.detections[0];
    const untrusted = report.hints.some(h => h.hint === "low_correction_margin");
    // null = not judged (a budget cut, or no score in this profile), never 0
    return { ok: true, text: d.content.text, kind: d.payload.kind,
             score: report.score?.value ?? null,
             final: report.trace.budget_exhausted === false, untrusted };
  } catch (e) {
    const code = (e as Error).message.match(/QRS-\d{3}/)?.[0];
    throw createError({ statusCode: code === "QRS-001" ? 422 : 413 });
  }
});
```

`d.content.text` is a complete reading of the payload's bytes
(`d.content.raw`, base64: the original bytes for the QR family, the
decoding engine's reading for other symbologies) unless
`d.content.charset === "unknown"` — the
only lossy value: then there is no verified reading, use `raw`. The
`Charset` type has six values (`utf8`, `shift_jis`, `latin1`, `gb18030`,
`eci`, `unknown`); give an exhaustive switch a default arm, since a later
release can add values (each a complete reading). Deduplicate on
`symbology`, `raw`, `fnc1` and `eci`, never on `text`.

Errors reject with `[QRS-xxx]`-tagged messages ([catalog](/api/errors)).
The report shape is the [one contract](/api/report).
