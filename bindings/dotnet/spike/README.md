# .NET through UniFFI · a spike

> **Not a package.** Nothing here is published and nothing here is an API to depend on. It is
> the spike the owner asked for before a .NET binding is written (decision of 11 November 2026:
> UniFFI for .NET, confirmed by a spike first).

The question: does C# generated by
[uniffi-bindgen-cs](https://github.com/NordSecurity/uniffi-bindgen-cs) load the engine's
existing UniFFI library, the one the Kotlin and Swift bindings already use, and scan in process?

The workflow [`.NET UniFFI spike`](../../../.github/workflows/dotnet-uniffi-spike.yml) answers
on Linux x64, macOS arm64 and Windows x64, from one commit each time:

1. it builds `crates/qrcode-ai-scanner-uniffi` with its locked UniFFI;
2. it generates the C# from that very library, with the generator release that targets the same
   UniFFI line;
3. it builds [`Program.cs`](Program.cs), which scans the mixed fixture with the three profiles
   and writes each report unchanged;
4. the destination acceptance driver judges the three reports.

The generated C# and the native library are never checked in: generating both from one commit
is what keeps their contract checksums equal.

`facts.json`, uploaded with the receipt, holds what the spike measured: the time of each scan,
the exception a file that is not an image raises, and the host.
