Use this binding when a C# service or desktop application already holds image bytes and needs the scanner report without starting a subprocess. The managed package loads its bundled native library on the supported operating systems. Its target framework, native runtime floors and choice of package source below are part of the installation contract.

The [QR code scanner](https://qrcode-ai.com/en-US/qr-code-scanner) and [barcode scanner](https://qrcode-ai.com/en-US/barcode-scanner) are QR Code AI’s browser scanning entry points. For the corresponding development route, the [QR code scanner .NET guide](https://qrcode-ai.com/en-US/qr-code-scanner/sdk/dotnet) and [barcode scanner .NET guide](https://qrcode-ai.com/en-US/barcode-scanner/sdk/dotnet) connect this documentation to the two product journeys. If a product page is unavailable, the instructions and references in this README remain the starting point for this source directory.

To prepare a sample image for a C# import workflow, use the [QR code generator](https://qrcode-ai.com/en-US/qr-code-generator) or the [barcode generator](https://qrcode-ai.com/en-US/barcode-generator). Keep the original payload with the exported image so that you can compare the scan result with the value you intended to encode.

Read QR codes and barcodes from an image in C# and .NET, in process. This package holds the
[QR Code & Barcode Scanner engine](https://github.com/qrcode-ai-com/qrcode-barcode-scanner)
itself, as a native library, and returns its JSON report unchanged. There is no command to
install and no network call.

## Choose a package source

The package id is `QRCodeAI.QRCodeBarcodeScanner`. Check its
[NuGet version history](https://www.nuget.org/packages/QRCodeAI.QRCodeBarcodeScanner)
before choosing a public version: a source tag or downloadable workflow archive does not
establish that the same version is on nuget.org. The commands below pin the version of this
source edition. For an unreleased candidate, install the qualified workflow archive from a
folder instead of asking the public feed for it. Maintainers can follow the
[publication setup and release checks](https://github.com/qrcode-ai-com/qrcode-barcode-scanner/blob/main/bindings/dotnet/PUBLISHING.md).

## What you need

Install the [.NET 10 SDK](https://dotnet.microsoft.com/en-us/download/dotnet/10.0) to build and
run the complete example below. The library itself targets `net8.0`; binding tests run on
.NET 8 and .NET 10. The framework target is a compatibility floor, not a promise that Microsoft
still supports every runtime that can load it. Choose an operating system supported by your
[.NET runtime](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)
and by the native library in this package.

The package contains five native libraries: Linux x64 and arm64 with glibc 2.28 or later,
macOS Intel with a native deployment floor of 10.15, macOS Apple silicon with a native floor
of 11, and Windows x64. These native floors are checked from the files themselves; they do
not lower .NET's own operating-system requirements. Clean package consumers run on Ubuntu
24.04, macOS 15 and Windows Server 2025, rather than on every older system above those floors.
Alpine/musl, Windows arm64, browser WASM, trimming and Native AOT are not qualified by these
checks. Use the separate browser package for a browser application.

## Install in a new C# project

Create a console project with the SDK installed above:

```sh
dotnet new console --name ScannerExample --framework net10.0 --no-restore
cd ScannerExample
```

For a version listed on nuget.org, install it with an explicit version:

```sh
dotnet add package QRCodeAI.QRCodeBarcodeScanner --version 0.11.0
```

For a candidate, use this alternative command in the same project. First download the
`dotnet-package` artifact from the repository's `.NET binding` workflow and extract it into
a local folder. Replace the path with that folder, which must contain the inspected `.nupkg`:

```sh
dotnet add package QRCodeAI.QRCodeBarcodeScanner --version 0.11.0 --source /absolute/path/to/qualified-archive
```

The folder route needs no NuGet publisher account and does not publish anything. Keep the
archive's version, source commit and SHA-256 receipt together; do not use an archive from a
different commit as evidence for this source edition. Neither route installs `qrscan` or
requires a separate native-library download.

## Scan an image

Save a PNG, JPEG, WebP or GIF as `label.png` in the project folder. For a reproducible first
run, download the repository's mixed QR and Code 128 fixture (use `curl.exe` in PowerShell):

```sh
curl --fail --location --output label.png https://raw.githubusercontent.com/qrcode-ai-com/qrcode-barcode-scanner/v0.11.0/fixtures/symbology/mixed-code128-qr.png
```

Replace the generated `Program.cs` with this complete program:

<!-- executable-example:Program.cs -->
```csharp
using QRCodeAI.QRCodeBarcodeScanner;

if (args.Length != 1)
{
    Console.Error.WriteLine("Usage: dotnet run -- <image-path>");
    return 2;
}

try
{
    var report = Scanner.Scan(File.ReadAllBytes(args[0]),
        new ScanOptions { Profile = ScanProfile.Full, BudgetMs = 0 });
    Console.WriteLine(report.Json);
    return 0;
}
catch (ScanException error)
{
    Console.Error.WriteLine($"{error.Case}: {error.Code ?? "no engine code"}: {error.Message}");
    return 1;
}
```

Run it from the project folder:

```sh
dotnet run -- label.png
```

The example prints the engine's JSON report unchanged. The mixed fixture contains the QR
payload `https://qrc-ai.com/76xMa` and the Code 128 payload `STOCK-4827`; both should appear in
`detections`. The program prints those values as data and does not open the QR link. A valid
blank image produces a successful empty report. Bytes that are not an image produce exit
code 1 and the `QRS-001` refusal on standard error. A missing file is an ordinary .NET file
error, separate from a scanner refusal.

`BudgetMs = 0` removes the time limit for this reproducible example. Choose a finite budget
for latency-sensitive work and inspect `Complete` before interpreting a partial result.
Scanning runs synchronously; a desktop application's UI thread should not perform a long
scan directly.

`Scanner.Scan` takes the bytes of a PNG, JPEG, WebP or GIF file. `Scanner.ScanFrame` takes raw
pixels, four bytes per pixel in red, green, blue, alpha order, with the width and the height.
Both run on the calling thread and return when the scan is done, and both are safe to call from
several threads.

Options are one record. Every value left out keeps the engine's own default:

```csharp
var report = Scanner.Scan(image, new ScanOptions { Profile = ScanProfile.Fast, BudgetMs = 0 });
```

| Profile | What the engine does |
| --- | --- |
| `ScanProfile.Frame` | Decodes only. The report carries no score. The default of `ScanFrame`. |
| `ScanProfile.Fast` | Decodes first, with a reduced judgment. |
| `ScanProfile.Full` | Decodes and judges how well a QR code scans. The default of `Scan`. |

| Option | Meaning |
| --- | --- |
| `BudgetMs` | The time budget in milliseconds. Left out, the profile keeps its own budget and a busy machine can cut the scan short. `0` sets none: the result then does not depend on how busy the machine is. |
| `MaxDimension`, `MaxPixels` | The largest image accepted. A larger one is refused before it is decoded. |
| `ScoreSkipAxes`, `ScoreSkipChecks`, `ScorePreset` | Which parts of the score are left out. A preset and skipped axes cannot be given together. |
| `AlphaBackground`, `AlphaPalette` | What a transparent image is laid over, and the backgrounds a transparent code must scan over. |

The values each option takes are those of the engine: see the
[option domains](https://github.com/qrcode-ai-com/qrcode-barcode-scanner/blob/v0.11.0/spec/02-profiles.md).

## Read the report

`report.Json` is the exact text the engine returned. Nothing is renamed, rounded or
recalculated, so decode it yourself for the payload, the measured places and the trace. It
follows the engine's [report contract](https://github.com/qrcode-ai-com/qrcode-barcode-scanner/blob/v0.11.0/spec/01-report.md). The other members read the
most used parts:

| Member | Meaning |
| --- | --- |
| `Found` | At least one code was decoded. |
| `Detections` | One entry per distinct content: `Symbology`, `Text` and `Raw`, the exact bytes. |
| `Score` | The scannability judgment from 0 to 100, or `null`. |
| `Complete` | `false` when the time budget cut the scan. |
| `EngineVersion` | The engine that wrote the report. |

Three things are easy to get wrong:

- **No code is a result, not an error.** `Found` is `false` and nothing is thrown.
- **A missing score is not zero.** `Score` is `null` with `ScanProfile.Frame`, or when the
  budget ran out before the judgment.
- **An incomplete scan proves nothing.** When `Complete` is `false`, an empty report does not
  mean the image holds no code. Scan again with a larger budget or with `BudgetMs = 0`.

Decoded text is untrusted data: a QR code can hold any text. Do not follow its links or run it.

## When something fails

Every refusal is one exception type, `ScanException`. Its message is the engine's own sentence.

| `Case` | When | `Code` |
| --- | --- | --- |
| `ScanFailed` | The engine refused the image or a limit: bytes that are not an image, an image above a limit, a frame whose size does not match its pixels, a limit of zero. | The engine's code, such as `QRS-001` for bytes that are not an image. |
| `UnknownAlphaBackground`, `UnknownPaletteColor`, `UnknownScorePreset`, `UnknownStressAxis`, `UnknownScoreCheck`, `PaletteTooLarge`, `ScorePresetConflict` | An option holds a value the engine does not know, or two options that cannot go together. | `null` |
| `EngineFault` | A fault inside the engine itself, not a refusal of your input. | `null` |

The codes are listed in the engine's [error catalog](https://github.com/qrcode-ai-com/qrcode-barcode-scanner/blob/v0.11.0/docs/api/errors.mdx).

## How it is built

The package is a thin layer over the engine's UniFFI library, the same one the Kotlin and
Swift bindings use. Two inputs are produced by the workflow from one commit and are never
checked in:

- the native library, built from `crates/qrcode-ai-scanner-uniffi` with its locked UniFFI;
- the C# that [uniffi-bindgen-cs](https://github.com/NordSecurity/uniffi-bindgen-cs) generates
  from that very library, at the release of the same UniFFI line. It stays internal: the public
  API is the six types of this folder.

Generating both from one commit is what keeps their contract checksums equal. The workflow
`.NET binding` of the engine repository (`.github/workflows/dotnet.yml`) does it on each change:

- on three systems it runs the tests of this folder on .NET 8 and on .NET 10;
- it builds the native library for the five systems at the floors above, and a program reads
  each file to check what it needs from the system that loads it;
- it packs the archive, inspects it file by file, then on the five systems a clean project
  installs it from a folder, scans the engine's mixed fixture with the three profiles and
  removes it. The engine's acceptance driver judges those scans;
- in a separate fresh .NET 10 project on each of those five hosts, it extracts the complete
  `Program.cs` above from the README actually installed by NuGet, checks the installed archive
  and README bytes against the candidate, and executes the mixed, blank and malformed inputs.
  The receipt retains the archive, README and program hashes, runtime and source commit.

These checks qualify the candidate they name. They do not establish a public NuGet release
or qualify a future archive before that archive passes the same checks.
