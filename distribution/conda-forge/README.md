This folder holds two conda-forge recipes for qrscan 0.11.0, in the format of the staged-recipes repository (recipe.yaml, schema version 1). They are not submitted yet.

- `recipes/qrcode-barcode-scanner-cli` builds the `qrscan` command from the [release source archive](https://github.com/qrcode-ai-com/qrcode-barcode-scanner-rust/releases/download/v0.11.0/qrcode-barcode-scanner-cli-0.11.0-source.tar.gz) of tag v0.11.0. This is the main recipe.
- `recipes/qrcode-barcode-scanner` builds the Python module `qrcode_barcode_scanner` from its PyPI source distribution 0.11.0. It is optional and can be submitted later.

The [QR code scanner](https://qrcode-ai.com/en-US/qr-code-scanner) and the [barcode scanner](https://qrcode-ai.com/en-US/barcode-scanner) let you try the engine in a browser first. For the qrscan options and its JSON report, read the [QR code scanner command line guide](https://qrcode-ai.com/en-US/qr-code-scanner/cli) and the [barcode scanner command line guide](https://qrcode-ai.com/en-US/barcode-scanner/cli).

To make a test image with a known payload, use the [QR code generator](https://qrcode-ai.com/en-US/qr-code-generator) or the [barcode generator](https://qrcode-ai.com/en-US/barcode-generator), and keep the payload you encoded to compare it with the scan.

## What the recipes do

The CLI recipe installs only the `qrcode-barcode-scanner-cli` crate from the [release source archive](https://github.com/qrcode-ai-com/qrcode-barcode-scanner-rust/releases/download/v0.11.0/qrcode-barcode-scanner-cli-0.11.0-source.tar.gz) of tag v0.11.0, with the exact crates of its `Cargo.lock`. It keeps the workspace release profile: integer overflow stays checked in the rxing reader, and `panic=abort` is never set, because the engine catches reader panics. It runs `cargo auditable install`, writes the licenses of every crate with `cargo-bundle-licenses`, and tests the installed command: `qrscan --capabilities`, then [test-scan.sh](recipes/qrcode-barcode-scanner-cli/test-scan.sh) on Linux and macOS or [test-scan.bat](recipes/qrcode-barcode-scanner-cli/test-scan.bat) on Windows. The check scans the [mixed QR and Code 128 sample](https://github.com/qrcode-ai-com/qrcode-barcode-scanner-rust/blob/v0.11.0/fixtures/symbology/mixed-code128-qr.png) with the fast, frame and full profiles and no time budget, and requires both payloads, `https://qrc-ai.com/76xMa` and `STOCK-4827`, in each report.

The Python recipe builds the sdist with maturin and tests the module with [test_scan.py](recipes/qrcode-barcode-scanner/test_scan.py). The test requires exactly the QR code and the Code 128 in each profile, with no cut budget and no reader panic.

## Install, once it is published

```sh
conda install -c conda-forge qrcode-barcode-scanner-cli
qrscan photo.png
```

qrscan prints a JSON report on stdout. It exits with 0 when it found at least one code, 1 when it found none and 2 when the image could not be read.

## How it is tested

`scripts/check-packaging-recipes.py` validates both recipes against the JSON schema of the recipe format (commit `7be6ba9f` of `prefix-dev/recipe-format`), and checks the version, the license, the archive digest and the test. `test_scan.py` passed against the published wheel 0.11.0 when the recipe was written. The build itself has not run: it compiles Rust, so it runs in the conda-forge CI after submission, or with `rattler-build build --recipe recipes/qrcode-barcode-scanner-cli/recipe.yaml` on a machine that may compile.

## Submit it

Submission is the owner's step, with the GitHub account `ThibautMelen`, which the recipes name as maintainer.

1. Fork `conda-forge/staged-recipes` and create a branch.
2. Copy `recipes/qrcode-barcode-scanner-cli` into the `recipes` folder of the fork.
3. Open the pull request to `conda-forge/staged-recipes` from `ThibautMelen` and follow its checklist.
4. After the merge, conda-forge creates the feedstock `qrcode-barcode-scanner-cli-feedstock`. Install the package from conda-forge and run the mixed sample to read it back.

      <img src="https://raw.githubusercontent.com/qrcode-ai-com/qrcode-barcode-scanner-rust/main/docs/assets/brand/formats-light.gif?v=bdfe5fc5f9b3" alt="The code families the engine reads: QR codes, matrix and stacked codes such as Data Matrix, retail barcodes such as EAN-13, and other linear barcodes such as Code 128" width="100%">

</p>

The same engine reads every destination’s images, so codes of different formats in one image come back in one report.

- QR: QR Code, Micro QR, rectangular Micro QR (rMQR)
- Matrix and stacked: Data Matrix, Aztec, PDF417, MaxiCode
- Retail: EAN-13, EAN-8, UPC-A, UPC-E
- Other linear: Code 128, Code 39, Code 93, Codabar, ITF, GS1 DataBar, GS1 DataBar Expanded, Telepen

The engine’s [supported formats](https://github.com/qrcode-ai-com/qrcode-barcode-scanner-rust#supported-formats) section states the known limits.
