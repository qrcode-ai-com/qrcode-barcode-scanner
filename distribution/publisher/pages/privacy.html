Privacy

The QR Code & Barcode Scanner reads images on the computer, phone or server that runs it. Its code sends no image, no decoded text and no usage data to QR Code AI. It has no analytics, no telemetry, no account and no cookies.

Where an integration makes a network request, or runs inside a host that keeps its own records, the integrations below say so. This page describes the code; the source is public, so each statement can be checked in the scanner's repository.

The engine

The engine decodes the image bytes it is given and returns a report. It opens no network connection and keeps no copy of the image or of the report. Every package of the scanner and its command-line program run this same engine.

The JavaScript and WebAssembly package also contains an optional module that checks where a decoded web address leads. It sends a request only when an application calls it with a network function of its own. None of the integrations on this site calls it.

Decoded codes can contain personal data, such as a contact card, a ticket or a payment code. The report goes back only to the program or person that asked for the scan.

Integrations

Each integration is listed here with what it reads, stores and sends.

Browser extension
An image you drop, paste or choose is read in the browser and never sent. For an image you right-click on a page, the extension fetches that one image again from the site that served it: first without cookies, then, if the site refuses, with that site's own cookies. It stores only the scanner profile you last chose, in the extension's local storage, and copies text to the clipboard only when you click a copy button. Its privacy notice gives the details and the permissions.
Canva app
The only network request the app makes downloads the selected image from the temporary address Canva gives it. The engine reads the image in the app's panel, in the browser. The app has no cookies and no storage, and keeps nothing after you close it.
Adobe Express add-on
The add-on loads Adobe's add-on SDK from Adobe and its own files from its package, and makes no other request. Adobe Express renders the page inside the browser, and the engine reads that rendering in the add-on, in the browser. A file you choose is read the same way and is not uploaded. The add-on has no cookies and no storage, and keeps nothing after you close it.
WordPress plugin
The scanner runs in the visitor's browser, with code served by your own site. The image never leaves the browser and is discarded when the page closes. The plugin makes no request to another server, sets no cookie, uses no local storage and stores nothing in your database.
HTTP service
You run the service yourself; it scans the images sent to it. Each image stays in the service's memory for the time of its scan and is never written to disk or logged. The service logs one line per request: method, path, status and duration, with no image and no decoded text.
GitHub Action
The action downloads the scanner's command-line program and its checksum file from the scanner's GitHub releases, on the runner of your workflow. It scans the files of your repository there. The decoded texts become outputs of the step and appear in the job's log and summary, which GitHub keeps with the workflow run.
MCP server, agent skill and agent plugin
Scanning makes no network call: the server and the skill's helper read the image you name on your machine. Installing the server, or the engine the skill runs, downloads packages from npm. Your agent client sends its conversation, including the scan report, to the model you chose, under that client's own terms.
OpenClaw plugin bundle
Its setup installs a pinned version of the MCP server from npm into the plugin's own folder and writes a local record of that installation there. Scanning then works as for the MCP server.
VS Code extension and Obsidian plugin
Both run the engine inside the editor and make no network request. The Obsidian plugin saves your profile and format choices in its plugin data. Both copy text to the clipboard only when you choose to copy it.
Raycast extension
It scans the image selected in Finder, or the image file on the clipboard, with the scanner's command-line program installed on your Mac. It makes no network request.
n8n, Node-RED and Activepieces
The node or piece runs the engine on the server of your automation platform and makes no network request. What the platform records about each run follows that platform's own settings.
Apify Actor
The Actor runs on Apify's platform, under your Apify account. It downloads each image address you give it, stores the images nowhere and keeps only the result items in your dataset, under your account's storage retention. It never opens what a code points to.
Dify plugin
The plugin reads the file your workflow gives it inside your Dify plugin runtime and keeps nothing. Dify itself stores files, workflow runs and logs as your Dify installation is configured. Its privacy notice gives the details.
ComfyUI nodes and napari plugin
They scan the images of your graph or viewer on your machine and make no network request.

This site

This site has no cookies, no analytics, no scripts and no external fonts. GitHub hosts it on GitHub Pages. GitHub states that when a GitHub Pages site is visited, the visitor's IP address is logged and stored for security purposes; see What is GitHub Pages?
