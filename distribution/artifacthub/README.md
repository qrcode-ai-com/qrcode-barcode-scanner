This folder prepares the Artifact Hub listing of the container image `ghcr.io/qrcode-ai-com/qrcode-barcode-scanner`, version 0.11.0. Artifact Hub reads a container listing from the annotations of an image index, and from a small metadata file stored in the same registry repository. Nothing here rebuilds the image: the listing reuses the two published platform manifests by digest, byte for byte. Nothing is listed on Artifact Hub yet.

The [QR code scanner](https://qrcode-ai.com/en-US/qr-code-scanner) and the [barcode scanner](https://qrcode-ai.com/en-US/barcode-scanner) let you try the engine in a browser first. To run the image with a mounted file, read the [QR code scanner Docker guide](https://qrcode-ai.com/en-US/qr-code-scanner/docker) and the [barcode scanner Docker guide](https://qrcode-ai.com/en-US/barcode-scanner/docker).

To make a test image with a known payload, use the [QR code generator](https://qrcode-ai.com/en-US/qr-code-generator) or the [barcode generator](https://qrcode-ai.com/en-US/barcode-generator), and keep the payload you encoded to compare it with the scan.

## Why a new tag

The published index of tag `0.11.0` has eight annotations. It lacks two keys that Artifact Hub needs: `org.opencontainers.image.created` and `io.artifacthub.package.readme-url`. That index is frozen by the release record of the image, so the listing uses a new tag, `0.11.0-r1`. Its index names the same two manifests, amd64 `sha256:4dfcdfb66730e191176be72df398e0dadec15ed6dab25227149375fb3931f42c` and arm64 `sha256:8720bf185c698747893fbd67d33bda9f42ffa99ef86af094fbaa7e4a9298a359`. It keeps every original annotation and adds the listing keys: creation time, license `AGPL-3.0-or-later`, vendor, keywords, logo, maintainer and the address of [LISTING.md](LISTING.md) at a fixed commit.

## Files

- [artifacthub-repo.yml](artifacthub-repo.yml): the repository metadata, with the owner and a placeholder for the repository ID.
- [published-index-0.11.0.json](published-index-0.11.0.json): the exact bytes of the published index of tag `0.11.0`, digest `sha256:fd0433f29b0dabd469ce6a8fdcfc7bf6554960301b5bc57b5fca97928fd7cb96`.
- [compose-index.py](compose-index.py): writes the listing index from those bytes and checks the pushed tag.
- [LISTING.md](LISTING.md): the page that Artifact Hub shows for the package.

## How it is tested

`compose-index.py --self-test` checks that the script refuses an index that is not the published one, a short commit, an annotation it would overwrite and a folder that is not empty. A compose with `--fetch` read the index, both manifests and both image configurations from the registry anonymously, and every digest, size and creation time matched the pinned values. `scripts/check-packaging-recipes.py` checks that the recorded bytes still hash to the published digest.

## Publish it

Publication is the owner's step. It needs an account that can write to `ghcr.io/qrcode-ai-com/qrcode-barcode-scanner`, the `oras` client, and an Artifact Hub account (sign in with GitHub).

1. Merge this folder, then note the full 40-character commit of `main` that holds this LISTING.md.
2. Run `python3 distribution/artifacthub/compose-index.py compose --readme-commit COMMIT --out /tmp/artifacthub-index --fetch`.
3. Push the index under the new tag: `oras manifest push --media-type application/vnd.oci.image.index.v1+json ghcr.io/qrcode-ai-com/qrcode-barcode-scanner:0.11.0-r1 /tmp/artifacthub-index/index.json`.
4. Check the pushed tag: `python3 distribution/artifacthub/compose-index.py verify-pushed --tag 0.11.0-r1 --expect /tmp/artifacthub-index/index.json`.
5. In the Artifact Hub control panel, add a repository of kind "Container images", name `qrcode-barcode-scanner`, display name "QR Code & Barcode Scanner", URL `oci://ghcr.io/qrcode-ai-com/qrcode-barcode-scanner`, and the tag `0.11.0-r1`. Copy its repository ID.
6. Put the ID in artifacthub-repo.yml and push the file under the tag `artifacthub.io`: `oras push ghcr.io/qrcode-ai-com/qrcode-barcode-scanner:artifacthub.io --config /dev/null:application/vnd.cncf.artifacthub.config.v1+yaml artifacthub-repo.yml:application/vnd.cncf.artifacthub.repository-metadata.layer.v1.yaml`. Artifact Hub then shows the repository as a verified publisher.

The email in artifacthub-repo.yml must be the email of the Artifact Hub account that adds the repository. The listing shows version `0.11.0-r1`; users who need the original tag can still pull `0.11.0`, which holds the same image.

The same engine reads every destination’s images, so codes of different formats in one image come back in one report.

- QR: QR Code, Micro QR, rectangular Micro QR (rMQR)
- Matrix and stacked: Data Matrix, Aztec, PDF417, MaxiCode
- Retail: EAN-13, EAN-8, UPC-A, UPC-E
- Other linear: Code 128, Code 39, Code 93, Codabar, ITF, GS1 DataBar, GS1 DataBar Expanded, Telepen

The engine’s [supported formats](https://github.com/qrcode-ai-com/qrcode-barcode-scanner-rust#supported-formats) section states the known limits.
